验收结论：整合 Harness 不通过

组件级开发基线可“有条件通过”，但当前没有纵向 Agent Loop、Verification Gate、持久 Thread、可运行客户端和 Win7 实机证据。不得宣称产品完成或可生产交付。

4. Win7 限制与 Agent 设计问题的边界

确属 Win7/EOL 硬约束

ConPTY 不存在；Job Object 嵌套能力弱；现代 Chromium/Electron/Node/Git 无受支持版本；根证书、TLS 1.2、SHA-2 补丁和老显卡驱动存在系统性风险。

必须通过原生 helper、fail-closed、远程执行、网络分段、工件锁定和实机证据应对；其中 EOL 风险只能接受/隔离，不能被“修复”。

不是 Win7 导致的 Agent 设计缺口

Thread/Run 持久化、事件 sequence/idempotency、Context 预算、ToolSpec、严格 Replay、Verification Gate、EvidenceBundle、App Server、UI、Trace/Eval、配置与秘密管理。

这些能力在任何操作系统上都需要实现；不得用 Win7 兼容性解释缺失。

阶段或证据未完成

SPIKE_01~04、企业 E7、Win7 E1/E2/E5、安装包/升级/回滚和端到端场景尚未执行。

这是项目门禁或环境可用性问题，不等于平台“不可能”；在证据完成前状态只能是 PROVISIONAL/BLOCKED。

混合原因

真实 Runner 因 Win7 隔离能力受限而被正确阻断，但 GitAdapter 又绕过 Runner；Junction 需 Win32 API，但 Apply 未调用边界校验；DPAPI 需实机，但秘密管理整体也未设计。

平台限制解释“实现方式”，不能解释绕过统一边界或缺少端到端强制。

混合问题示例：真实 Runner 因 Win7 containment 未验证而 fail-closed 是正确设计；GitAdapter 直接 spawn 绕过该边界是设计错误。Win7 Junction 需要 Win32 API 是平台事实；Apply 不调用边界校验是架构缺口。

ENV-01 真实 containment / PTY 未验证 Win7 硬限制 + 阶段阻断 Win7 无 ConPTY，Job Object 存在嵌套限制；不能安全执行任意命令。 完成 SPIKE_02；若 No-Go，保持拒绝或把执行远程化。
