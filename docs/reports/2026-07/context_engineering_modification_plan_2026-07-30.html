上下文工程修改计划

从“有界条目选择器”演进为不可绕过、可追溯、缓存友好且具备工作记忆的 Context Harness。 本计划同时给出架构边界、文件级工作包、测试合同和阶段门禁。

角色：Agent 架构师 + Agent 研发工程师 日期：2026-07-30 分支：codex/integrated-robustness 基线：上下文工程验收 0/12 完整满足 模式：仅制定计划

计划结论

采用 7 个工作包、两道验收门 先关闭上下文投影与摘要完整性两个 P0，再建设 Bootstrap、分层规则、工作记忆、 输出治理、批量压缩和量化回归。不得在 P0 合同冻结前并行修改 Runtime/Gateway 的模型入参，否则容易形成第二套可绕过路径。
Gate A · v1 Context Core CE-01～04、06～12 完整；CE-05 完成常驻规则治理。
Gate B · 完整讲义对齐 v1.1 按 ADR-0035 实现按需 Skill 宿主后，CE-05 端到端完成。

当前工作树已出现第三讲之后的增量：State 投影现在能用 compaction.applied 的摘要替换消息范围。因此 CE-07 不再从零实现； 本计划复用该协议，重点补齐 Core 水位触发、可恢复引用和持久化边界。

更新性能权威表

按 ADR-0033 规则，为上下文占用、预留比例、压缩频率、初始 token 和缓存前缀稳定性 增加可测指标；未实测状态不得写成达标。

未完成 ADR 与任务书增补前，不进入应用代码修改。当前任务虽允许 src/core/**、src/state/**、Gateway 和验证脚本， 但现有授权没有冻结本次新的跨模块数据合同。

目标架构

1. Context Sources 固定系统版本、环境快照、分层规则、用户任务、事件历史、工具观察、工作记忆。
2. Ownership & Zones 区分 protected、stable-prefix、rolling-history、tail-memory；记录来源和 revision。
3. Context Compiler 精确顺序、token 估算、75% 水位、可逆折叠、内容摘要和 Manifest v2。
4. Model Projection 只暴露最终消息、排序后的 ToolSpec 和安全运行元数据；不暴露原始 RuntimeRequest。
5. Event Feedback 模型响应、计划更新、工具结果、用量和压缩全部进入 State V2，再投影下一 Step。
模型只看到投影。 Runtime/Gateway 模型端口不能拿到原始 contextItems、审批令牌、工作区写入对象 或未选择的历史。
约束与计划分权。 system/user/policy/project 规则由 Harness 管理；模型只能更新 plan/currentStep/findings。
摘要绑定实际内容。 每个条目包含 content SHA-256；整体摘要绑定内容、顺序、系统提示版本和工具目录摘要。
事件是事实，Context 是投影。 Runtime 内存消息不再作为恢复权威；压缩只替换投影，原始事实保持追加。

关键数据合同

合同 核心字段 不变量 迁移策略

工作包与文件级计划

WP0 · 决策与合同冻结 CE-01～12 / 必须先行

修改范围
  • docs/DECISIONS.md：追加 ADR-0043，不改既有 Accepted 正文。
  • docs/tasks/INTEGRATION_01_ROBUSTNESS_HARDENING.md：增加第四讲原子需求。
  • docs/PERFORMANCE_BUDGET.md：增加上下文指标，状态初始为 NOT_MEASURED。
  • docs/ARCHITECTURE.md：补充 Context Harness 分层与依赖方向。
冻结的选择
  • 默认投影水位 75%；至少保留 20%，另留约 5% 压缩/安全缓冲。
  • 压缩触发后目标回落到不高于 60%，避免每轮重压缩。
  • 产品级 Skill 宿主保持 v1.1；v1 只执行 AGENTS 常驻规则治理。
  • Manifest/Checkpoint 升级采用 fail-closed，不静默接受旧摘要。

退出条件：ADR Accepted、任务书状态和路径白名单无冲突、CE-01～12 均有确定性验收条目。

WP1 · P0 投影完整性与不可绕过边界 CE-01 / P0

研发动作
  • 新增 src/core/src/context-types.ts，定义 v2 条目、分区、来源和投影 DTO。
  • 重构 context-manager.ts：内容哈希、规范顺序、保护区、预留和 Manifest v2。
  • 收紧 runtime.ts：RuntimeModelInput 删除 request，只传最终投影。
  • 新增 src/core/src/token-estimator.ts：可注入估算器；fallback 采用保守 UTF-8 字节估算并标注精度。
  • Gateway 增加 RuntimeModel Adapter，只序列化 projection；ToolSpec 先按名称再按 schema digest 固定顺序。
必须新增的负向测试
  • 同长度 ALLOW → DENY! 必须改变 digest。
  • 条目顺序、系统提示版本或工具 schema 任一变化必须改变 projection digest。
  • 模型输入对象中不存在原始 contextItems、审批 token 和未选条目。
  • protected 条目超过硬上限时返回 CONTEXT_PROTECTED_BUDGET_EXCEEDED，禁止静默丢弃。
  • 旧 v1 Checkpoint 恢复明确拒绝；v2 内容漂移审批失效。

退出条件：预算选择成为模型调用唯一事实；P0-1、P0-2、P0-3 三项均有自动化回归，静态设计门可阻止接口回退。

WP2 · 最小 Bootstrap、环境快照与分层 AGENTS CE-02～05

研发动作
  • 新增 context-bootstrap.ts：只装载固定系统版本、环境、规则、任务，不读 README/目录树/源码。
  • 新增 agents-discovery.ts：用户规则路径 + repo root → cwd，近处规则后置。
  • 环境字段：workspace cwd、实际 host/目标平台、Shell Profile、日期、审批模式、Git 分支/dirty/可用性。
  • Git 状态必须来自专用 Git Adapter；不得为环境消息新增直接 child_process。
  • 规则文件使用 UTF-8、显式字节预算、realpath 边界和结构化 warning。
验收场景
  • 根与子目录规则冲突时，模型投影顺序严格为 root 在前、child 在后。
  • 默认初始投影不含 README、完整目录树和源码片段。
  • 动态日期只在环境消息中，系统前缀 digest 同一天内稳定。
  • Git 缺失或受控 Runner 不可用时环境结构化降级，不崩溃、不直接 spawn。
  • 中文、空格、反斜杠、长路径和 reparse/symlink 越界负向测试。

CE-05 的 v1 验收只证明“常驻规则与任务流程不混放、任务流程不自动注入”。 按需 Skill 发现与执行仍由 ADR-0035 留给 v1.1，不得在本工作包偷渡插件宿主。

退出条件：初始上下文类别白名单、环境快照和规则作用域均有生产入口与冲突顺序测试。

WP3 · 工作记忆、复诵与约束所有权 CE-08～09

研发动作
  • 新增 working-memory.ts：目标、受保护约束、计划、当前步骤、发现和 revision。
  • 增加 Harness 内部控制工具 agent.update_plan，与 Workspace/Runner 外部工具路由隔离。
  • 在 State V2 增加 working_memory.initialized、plan.updated、finding.added、constraint.superseded。
  • 每个模型 Step 最后一条上下文固定为 WorkingMemory 投影；原始事件仍在前缀历史中追加。
  • Checkpoint 只引用 working-memory revision 与投影摘要，不保存可漂移的平行副本。
权限与测试
  • agent.update_plan 仅允许修改 plan/currentStep/findings。
  • 尝试删除、覆盖或降级 system/user/policy/project constraint 必须拒绝并事件化。
  • 同 revision 重试幂等；跨 revision 冲突拒绝。
  • 工作记忆始终位于消息尾部；无论压缩还是审批恢复，约束 digest 不变。
  • 模型可提议约束变更，但必须由来源控制面另行 supersede。

退出条件：20 Step 之前的单元级 recitation 测试通过；模型无法通过工具或 plan 响应删除硬约束。

WP4 · Agentic Retrieval 输出合同与可逆折叠 CE-06～07

研发动作
  • 新增 tool-observation.ts，统一 search/read/list/Runner 的返回元数据。
  • search 返回 returned、total 或 at_least 下界；read 使用行号、范围和 next cursor；list 默认浅层。
  • Runtime 不再直接 JSON.stringify 任意 result；先经 Observation Formatter 和上下文预算。
  • 复用 State 当前 compaction range + summary，增加 source refs、内容摘要与再读取入口。
  • 只有可重建或原始事件已可靠保存的输出才能折叠；不可恢复的临时输出不得假装可恢复。
验收场景
  • 超长 search/read/list/command 分别命中字节、条目、匹配数限制并报告真实原因。
  • 截断结果包含 omitted 数量或下界、cursor 与 content digest。
  • 折叠后投影只含摘要和引用，原始 State 事实数量不减少。
  • 引用文件内容发生变化时，旧 snapshot hash 被识别，不把新内容冒充旧观察。
  • 多个 compaction 通过 supersedes DAG 只激活最新版，范围不得重叠冲突。

退出条件：所有进入模型历史的工具观察均有统一上限和截断语义；CE-07 从“协议雏形”升级为 Core→State→再投影闭环。

WP5 · KV Cache、水位压缩与上下文遥测 CE-01、10～11

研发动作
  • 新增 context-watermark.ts：75% 触发、压缩后不高于 60%、至少 20% 输出预留。
  • 固定系统提示版本；ToolSpec 规范排序和 catalog digest；历史只追加。
  • Context telemetry 记录各分区 token、总输入、预留、折叠次数、prefix digest 和 provider usage。
  • 仅在跨越水位时批量压缩；禁止每轮小改历史。
  • 在 Performance Budget 记录典型任务删减前后输入 token，不把未实测指标写成通过。
验收场景
  • 只更新尾部工作记忆时 stable-prefix digest 不变。
  • ToolSpec 注册顺序不同，最终 catalog 顺序和 digest 相同。
  • 水位以下不压缩；第一次越线只产生一次 compaction；回落后下一 Step 不重复压缩。
  • 输入永不超过 hard limit；output/compression reserve 可在 Manifest 复算。
  • 基准报告同时给出 legacy 与新投影的初始、累计、缓存前缀 token；无结果时标不可验证。

退出条件：缓存友好性由稳定摘要和确定性测试证明；token 对照报告可重复生成，压缩不会删除事实事件。

WP6 · 20+ Step 验收、集成回归与 Win7 门禁 CE-12 / 最终门

确定性场景
  • 构造 24 Step Replay：检索、读取、计划更新、工具错误恢复、一次压缩、一次审批挂起/恢复。
  • 每 Step 断言目标、protected constraints、plan revision、prefix digest 和 ContextManifest。
  • 末尾 Verification Gate 检查目标完成；任何约束丢失、未配对工具结果或摘要漂移均失败。
  • 同时执行模型失败、State 写入失败、预算耗尽和旧 Checkpoint 负向矩阵。
平台与发布边界
  • 根级 npm run verify 增加 Context Harness 静态设计门。
  • Core、State、Gateway 定向测试后执行七模块全量 lint/build/test。
  • Win7 验收覆盖中文路径、CP936 环境、Git 缺失、机械盘和低内存；开发机结果不替代实机。
  • SQLite 持久化与跨重启恢复继续受 SPIKE_04；未完成时 Gate A 只能标记开发机合同通过。

退出条件：24 Step 场景无目标漂移；CE-01～04、06～12 从验收矩阵转为 implemented；CE-05 明确记录 v1 与 v1.1 的边界。

风险、回滚与非目标

风险 控制措施 回滚/失败语义
RuntimeModelInput 破坏性变更 一次冻结 Projection DTO；同步迁移全部 Mock/Gateway Adapter；静态扫描禁止旧字段。 不保留双路径兼容开关；编译失败比运行时绕过更安全。
Protected 内容本身超过窗口 启动前估算；给出最大规则文件与来源明细。 结构化失败，不删除 system/user/policy 约束。
压缩摘要丢失关键事实 摘要必须保留目标、约束、未决工具、审批和关键发现；验证器检查摘要合同。 摘要验证失败则不提交 compaction，保留原投影并请求新 Turn。
Git 环境快照绕过 Adapter Environment Provider 只依赖 Git Adapter 端口；根级静态门禁止直接 spawn。 能力不可用时显示 unknown/degraded，不猜测分支状态。
事件与内存工作记忆分叉 State V2 为唯一事实；内存对象只能由事件投影生成。 revision/digest 不匹配时 fail-closed，禁止继续恢复。

本计划明确不做：

  • 不在本轮实现 v1.1 插件/Skill 宿主、MCP 或 Hooks。
  • 不借上下文工程实现真实 Runner、Job Object、交互终端或 Win7 containment。
  • 不引入向量数据库或仓库 Embedding；主路径保持 Agentic Retrieval。
  • 不把内存 State、Mock Gateway 或开发机测试解释为 SQLite、Win7 或生产交付完成。
  • 不整体合并/cherry-pick Phase 2 legacy；仅按任务书迁移矩阵重构其有界输出合同。

最终完成定义

  1. 模型只能接收 Context Projection，无法访问未选上下文或原始 RuntimeRequest。
  2. 内容、顺序、系统提示版本或工具 schema 变化均能导致摘要变化。
  3. 硬约束不会因预算、压缩或模型工具调用而消失；来源控制面可追溯地 supersede。
  4. 初始上下文不默认包含 README、目录树或源码；AGENTS 严格 root→cwd。
  5. 所有工具观察有界、显式截断、可分页；可恢复输出支持可逆折叠。
  6. 上下文达到 75% 才批量压缩，完成后回落到 60% 以下，并保留至少 20% 输出空间。
  7. 24 Step Replay 全程保持目标、约束和计划 revision，最终通过 Verification Gate。
  8. Core/State/Gateway 定向与根级全量验证通过；不可用检查仍明确标记 unavailable。
  9. Win7 实机与 SPIKE_04 未完成前，只能声明“开发机 Context Core 合同通过”。
