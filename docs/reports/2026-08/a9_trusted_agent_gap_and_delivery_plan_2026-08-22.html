哪些是 Win7 导致，哪些是设计导致

Win7 客观约束

  • 干净 Win7 的 PowerShell 版本不一致，可能只有 2.0；必须探测 5.1 并保留 CMD。
  • 没有 ConPTY，交互终端不应进入 Alpha 1；普通非交互 Shell 不受此限制。
  • Electron 22、Node 16、Git 2.46.2、WMF 5.1 均为 EOL 栈，需要固定工件和实机证据。
  • CP936、PowerShell 5.1 输出编码、传统 MAX_PATH、junction 和 Job 嵌套需要专门适配。
  • 不能假设有 Git、Python、Node、curl、Git Bash 或管理员权限，缺失时必须局部降级。

现有产品设计问题

  • Policy 明确拒绝 Full Access，并把 Shell 宿主列为 prohibited。
  • 正式工作区写入强制经过 Review staging，无法像主流 Agent 一样直接迭代。
  • Git 被隔离白名单限制，网络 Git 明确禁止，真实 hooks/helper 项目不能工作。
  • 正式 UI 默认 Replay；真实 Provider 固定 DeepSeek URL 和模型联合类型。
  • 文件工具面不完整，缺 copy/move/delete、轮级 checkpoint 和 Shell 外部变化恢复。
  • 项目 Runner 只有固定验收 Profile，无法运行真实项目测试和构建。

最高风险差距

  1. 通用 Shell 完全相反：Core Policy、NativeRunner 都主动拒绝 PowerShell/CMD/bash；不是 Win7 做不到。
  2. Full Access 不存在：PolicyEngine 对 full_access 明确返回 deny，桌面端只有只读或审批路径。
  3. 真实项目 Runner 未接通：Desktop Host 默认 UnavailableRunner，只有固定 acceptance action。
  4. Provider 伪开放：DeepSeek Provider 强制固定域名和模型；设置 UI 默认 Replay。
  5. 恢复粒度不足：Trusted write 只覆盖单文件 UTF-8 精确替换；A8 Review 不是 Full Access 每轮 checkpoint。
