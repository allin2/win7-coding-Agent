4. 串行工作分解与关键路径

M0 基线→M1 合同→M2 准备区→M3 Review→M4 Apply→M5 Validation→M6 Gate
M0

基线保护与测试夹具设计

记录当前 changed paths、验证结果、C14 白名单；冻结 create/modify/delete、编码/EOL、路径、漂移和故障注入 fixture 目录。

0.5 日
退出：可回退证据完整
M1

ReviewSetV1、状态机与摘要哈希

定义 Review/FileItem/ValidationRun，Windows case-fold 唯一键、canonical JSON、workspaceBase/preview/acceptedSet hash、revision 与原子事件。

1.5–2 日
覆盖：R01/R03
M2

私有准备区与多文件预览

写入 content-addressed blob；从可信 before bytes 构建 CREATE/MODIFY/DELETE 提案；生成统一 Diff、编码、BOM、EOL、字节数和 hash；敏感内容命中即清理。

2–3 日
覆盖：R01/R06/C01
M3

逐文件决定、Review 页面与精确 IPC

启用 Review 页面；文件列表、Diff、测试/未验证项；接受/拒绝不写工作区；全拒绝直接 REJECTED；任何决定变化提升 revision。

1.5–2 日
覆盖：R02/R03/C02
M4

一次性批量审批、漂移预检与全组回滚

审批绑定 session/task/review/revision/三个 hash/subject/expiry；先验证全部目标再写；accepted subset 单计划应用；故障未确认进入 RECOVERY_REQUIRED 并锁定。

2–3 日
覆盖：R04/R05/R06
M5

验证绑定与真实状态

ValidationRun 绑定 review revision 和 validated-set hash；显示 PASS/FAIL/CANCELLED/NOT_RUN、截断与适用文件；提案变化使结果 STALE。

1–2 日
覆盖：R07/C01
M6

A8-03 Gate 与证据收口

执行 A8R-01～07、A8C-01/02、旧 A2/A8-01/A8-02 回归、真实 Renderer 视觉 QA、全量 verify、文档和路径白名单检查；生成 Gate 报告。

1 日
退出：A8_03_REVIEW_APPLY_PASS

6. 验收策略与停止条件

每个工作包的验证阶梯

  • 最窄单元/合同测试
  • State + Workspace 原子行为测试
  • Product Host / IPC / Renderer 交互测试
  • A8R/A8C 确定性矩阵
  • npm run verify 全量回归
  • docs:check、JSON、diff、C14 白名单

不得以弱证据替代

  • 单文件 Diff 不等于多文件 Review
  • 模型“已测试”不等于 Validation PASS
  • 开发机任意 npm/pytest 不等于产品 Runner Profile
  • 部分写入后报告成功不等于批量原子
  • UI 卡片存在不等于副作用边界通过
  • A7 RC PASS 不继承给 A8
门禁必须同时证明
A8R-01～03权威事实、确定性投影、决定零工作区副作用、旧绑定失效
A8R-04～05漂移时零文件写入；所有故障点全组恢复；不确定时锁定
A8R-06UTF-8 BOM/UTF-16/GBK/CRLF/mixed EOL 按支持策略逐字节验证
A8R-07真实适配器事实、取消/失败/截断/STALE/NOT_RUN 均准确
A8C-01/02敏感值零明文命中；未登记 IPC/能力零副作用并可审计

7. 风险、依赖与裁决点

关键外部依赖：当前产品 manifest 只登记 win7-whoami，它不能执行真实项目测试。M5 可以完成 ValidationRun、NOT_RUN、失败/取消/截断和 stale 语义，但在没有经 C15/C16 登记并实测的低风险项目测试 Profile 前，不得宣称“真实项目测试 PASS”，也不得把开发机命令冒充产品证据。

风险预防措施触发后的动作
当前工作树跨 A8-00～02 且未提交M0 形成可回退证据，不触碰无关改动发现基线不一致立即停止实现并重新审计
冻结字段/哈希不足实现严格遵循 A8-00 §6需要改合同则新增 ADR 并重开 A8-00，不在代码中偷改
新增依赖/Profile/网络目标默认零新增依赖，复用现有模块先完成 C15/C16 登记和授权，再写实现
多文件 DELETE 回滚不完整删除前同样创建可信备份并做故障注入无法证明恢复即 RECOVERY_REQUIRED，锁定写入
编码被静默规范化以 bytes 为权威，metadata 显式展示不支持/二进制结构化拒绝，不做猜测写入
阶段越界A8-03 只实现 Review/Apply/Validation持久恢复、Terminal/Browser 分别留到 A8-05/A8-04
