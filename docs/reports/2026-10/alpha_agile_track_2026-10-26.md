## 1. 判断：现在的流程是按"成熟产品"校准的

当前交付链具备的全部特征，都属于产品定型之后才需要的东西：双干净构建逐字节比对、候选身份冻结、门 A/门 B 双签、197 份证据、288 条 ADR、61 份任务书。

而产品实际状态是：**两个可用能力模式（Full Access、Read Only），第三个（Review）仍 fail-closed。** ADR-0096 把 Review 延期到 `0.3.0-alpha.2`；ADR-0099 补充"Alpha 2 Review 必须另立任务书"；ADR-0100 再次写明"继续不在本任务范围"。alpha.2 已签发，该任务书未见立项。

结论：**用 RC 级的证据门槛，约束一个能力尚未补齐的 alpha 产品。** 这是流程与产品阶段错配，不是执行不力。

## 2. 三条量化证据

| 事实 | 数值 | 含义 |
|---|---|---|
| 产品代码产出 | WIN7-46→55 共 9 天、26 提交，`src/` 非测试改 **81 行**；两处提交都是 `fix`（控制管道失败、IPC 结构化错误） | 9 天约 9 行/天，且全是健壮性修复，**无新增能力** |
| 想法到可用版本 | 9 天 | 敏捷要求 alpha 期 ≤3 天可感知一次 |
| 能力增量 | Full Access + Read Only → 仍是 Full Access + Read Only | 一轮发布，能力集合没变 |

同期投入：文档 25,501 行、测试 4,744 行、证据 197 文件/轮、修复轮 14 个（ENGINEERING_04 事实 F1）。

**一句话**：流程产出的增长速度，是产品产出速度的 30 倍以上。

---

## 3. 核心矛盾

产品不成熟时，最大的风险是**做错方向**，不是**证据不严**。当前把几乎全部工程资源投向"证明已经做的东西是对的"，而没有任何机制回答"该不该做、有没有人用、值不值得继续"。

三个缺失：

1. **没有真实使用回路**。alpha.2 已发 GitHub Release，但没有任何 dogfood 记录或反馈通道；所有验证都是合成用例。
2. **没有范围决策点**。ADR-0288 管了流程节奏，没管范围；没有 feature freeze，也没有"砍需求"的机制。
3. **没有 DoD 分层**。只有一套 RC 级完成定义，任何改动都被迫走最重的路。

---

## 4. 双轨制：Alpha 轨与 RC 轨

把"发布"与"签字"解耦。两条轨道共用同一份源码与同一套安全红线，但证据强度与仪式不同。

| | **Alpha 轨**（每周） | **RC 轨**（里程碑 / 合同） |
|---|---|---|
| 触发 | 每周固定时间，或一个能力切片完成 | 对外里程碑、合同节点、发布正式版 |
| 候选身份 | commit sha，不换候选号 | 冻结候选号 + 双干净构建 |
| 必须通过 | Alpha-DoD（见下） | 11 阶段 / 37 用例 / 67 断言 |
| 证据 | 一页摘要 + 运行日志哈希 + commit | 全量证据 + 独立审核 + 门 A/B 双签 |
| 产物 | 预发布 build，标注 `ALPHA_UNVERIFIED` | 正式 Release，标注候选与已知限制 |
| 对人的承诺 | "可能坏，别用于生产" | "按合同判据通过" |

**Alpha-DoD（四条，缺一不可）**

1. 在**一台 Win7 实机**上完成一件真实任务：真实模型、真实文件、真实进程。
2. 四项安全行为不变：输出上限、进程树回收、凭据脱敏、TLS 默认验证。
3. 本地门（`test:local`）通过。
4. 产物标注 `ALPHA_UNVERIFIED`，不产生任何 `PASS` 结论，不进入证据账本。

**关键约束**：Alpha 轨的产物不得用于任何验收结论。术语表已有先例（Demo、解说材料不是证据），只需新增一个状态词 `ALPHA_UNVERIFIED`，不新增证据层级。

---

## 5. 按风险配证据

不成熟阶段最浪费的动作，是给低风险改动配高强度证据。按变更类型分档：

| 变更类型 | Alpha 轨 | RC 轨 |
|---|---|---|
| UI 文案、布局、日志措辞 | 截图 + 本地门 | 受影响用例 |
| `src/**` 非安全逻辑 | 本地门 + 单机 smoke | 受影响回归 |
| 夹具、验证脚本 | 本地表驱动 + `--check-only` | 全量彩排 |
| 安全模型、Policy、IPC schema、`native/`、打包判据 | **不进 Alpha 轨** | 门 A/B 全量 |

这张表是"任何文件都可以改"的具体答案：文件可以改，但**证据强度跟着风险走**，而不是跟着流程序号走。

---

## 6. 纵向切片，而不是横向分层

现在每个能力要同时横跨 main / Core / Shell 三层、夹具、证据包，才算"做完"。alpha 阶段应改为按**用户任务**切片：一条薄链从 UI 到 Runner 打通即算一个增量，先可用再加固。

- 每切片自带最小端到端检查，不追求全层完备。
- 度量从"用例通过率"改为"**每周可用能力数**"。
- 未被切片覆盖的层允许保持现状，不阻塞发布。

---

## 7. 时间盒与 WIP 上限

- **3 天一个 iteration**：到点只收已过 Alpha-DoD 的内容，其余回队列。当前模式是"改到 PASS 为止"，没有时间盒，这是 9 天只出 81 行的直接原因。
- **同时进行任务 ≤2**：一个产品切片 + 一个流程改进。当前 3 个工作树并行（32 GB），没有 WIP 约束。
- **一会话一 worktree，每日两次合并窗口**（与建议书 §11.6 同一条）。

---

## 8. 真实使用回路（当前完全缺失）

这是差距最大的一项，也是最便宜的：

1. **每周狗粮**：用 weekly build 完成一件真实工作，记录卡点。卡点清单比任何用例都能指导下一步优先级。
2. **内置反馈包**：版本 + 最近审计摘要 + 脱敏日志，一键导出。它属于**产品特性**，应进 backlog，不应作为流程工具。
3. **把卡点变成用例**：每个卡点补一条端到端检查，这就是"缺陷逃逸台账"（建议书 §11.8）的自然来源。

收益：现在的"下一轮该做什么"由证据缺口驱动；有了这条回路，改由真实卡点驱动。

## 9. 立即可以砍掉的六项（Alpha 轨内）

| 砍掉 | 理由 | 保留在 RC 轨 |
|---|---|---|
| 非 `native` 改动的双干净构建 | 只证明构建可重复，不证明产品可用 | 是 |
| 夹具数据改动的独立审核 | ADR-0288 已允许"只改数据"走自动校验 | 是 |
| 任务书 + 白名单（域 A/B） | 与建议书 §11.1 同一件事 | 域 C 保留 |
| 11 阶段全量 | 改 smoke 三项即可覆盖真实链路 | 是 |
| 197 文件证据包 | 改一页摘要 + 日志哈希 | 是 |
| 换候选号 | Alpha 轨用 commit sha 标识 | 是 |

---

## 10. 不能砍的四项

1. 四项安全行为（输出上限、进程树回收、凭据脱敏、TLS 默认验证）。
2. 只有 Win7 实机能产生 Win7 `PASS`——Alpha 轨只是不签 PASS，不是降低真机要求。
3. 私钥红线：不读取、不输出、不进 worktree。
4. Accepted ADR 正文不可改写。

---

## 11. 投入排序：按剩余轮数算，不按理论最优

优先级 = （每轮省时 × 预计剩余轮数）÷ 实施成本。

| 候选投入 | 每轮省时 | 实施成本 | 结论 |
|---|---|---|---|
| preflight（2 分钟判死） | 0.5~半天 | 0.5 人日 | **先做**，剩余轮数越多越值 |
| 本地门 + 修红灯 | 30 分钟 | 1~1.5 人日 | **先做** |
| 双轨制（纯文档 + 一个状态词） | 每轮数小时 | 1 人日 | **先做** |
| 证据账本 | 核验时间 | 2 人日 + ADR | 只出设计，等 RC 轨稳定再做 |
| ADR 压缩 | 上下文成本 | 持续 | 排最后 |

注意：如果剩余轮数只有 5 轮，证据账本这类一次性大投入的回收期就不成立——**不要因为"架构上更美"就现在做**。

## 12. 30 天节奏

| 周 | 内容 | 完成判据 |
|---|---|---|
| W1 | 定义双轨与 Alpha-DoD；新增状态词 `ALPHA_UNVERIFIED`；砍清单生效 | 一条 ADR 签发 |
| W2 | 本地门 + preflight 落地 | `test:local` 绿；preflight 2 分钟出 go/no-go |
| W3 | 第一个 weekly build 走通 Alpha 轨 | 单台 Win7 完成一件真实任务并留下记录 |
| W4 | 复盘 | 可用能力数、lead time、卡点数、返工率有数 |

**本阶段度量**（与成熟期 DORA 不同）：

| 指标 | 基线 | 4 周目标 |
|---|---|---|
| 可用能力数 / 周 | 0（9 天无新增） | ≥1 |
| 想法 → weekly build | 9 天 | ≤3 天 |
| 狗粮卡点数 | 无记录 | 有清单，且每条有归属 |
| 每轮固定税（人时） | 未测 | 下降一半 |
