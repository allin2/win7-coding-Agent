## 1. 结论

1. **当前流程的瓶颈不在"验收不够严"，在"本地没有任何强制信号"。** 仓库已有 2,073 个本地用例，但无 CI、无 pre-push；实测 `main` 上 5 个包各有失败用例。团队因此只能把物理机当唯一裁判——这是 40 分钟反馈回路的真正成因。
2. **9 轮失败的根因类别是"夹具在正式根下的行为从未被执行过"。** 这类缺陷可以在 macOS 上用表驱动用例拦下，不需要 Mock 整套 Windows 运行环境。
3. **单轮迭代成本的主要构成是"身份变更"而非"写代码"。** WIN7-46→WIN7-55 共 9 天、26 个提交，产品代码只改 81 行；同期文档改 25,501 行、测试改 4,744 行。
4. **治理成本已在 ADR-0288 被约束，但缺一条"分级"落地规则。** 288 个 ADR 里，测试参数与环境说明占了相当比例。
5. **第一部分建议按 P0（本地可信门）/ P1（夹具可预跑 + 治理分级）/ P2（验收分级 + 产物治理）推进。** P0 只需 1~2 人日，收益最大。
6. **第二部分的三条结构性改动比第一部分更值钱，但都需要负责人签**：授权按风险域（§11.1）、证据改为可查询账本（§11.3）、Alpha 退出条件（§11.10）。其中 §11.1 是唯一能一次性消掉"每轮固定税"的改动。
7. **`ENGINEERING_04` 草案已覆盖六项同类建议**（拒绝集、驱动出包、目录布局、大件预置、传输共用、审核分级）。本文不重复立项，只补它没覆盖的部分，映射见 §12。

## 4. 可改进性判定

| 判断                       | 依据                                                           |
| ------------------------ | ------------------------------------------------------------ |
| **真瓶颈是"信号可信度"，不是"测试数量"** | 2,073 个用例已覆盖状态机、脱敏、参数校验；缺的是让它们必须通过                           |
| **"建 Mock 替代物理机"不是对症方案** | 9 轮失败类别为夹具授权分支、PID 复用误判、容量上限、WMI 退出码、中继断线——Mock 对这批的拦截率接近 0  |
| **"夹具本地预跑"是对症方案**        | p05 根因是判定逻辑分支未覆盖，属纯函数可测范围                                    |
| **"拆分验收"必须保留门 A 判据才安全**  | 37/67 是门 A/B 的唯一判据；分级只能做"提前失败"，不能替换判据                        |
| **"放宽 C14"不可执行**         | AGENTS.md §4 与 ADR-0192 明确禁止通过修改白名单或临时豁免绕过；C14 的防护对象正是验收代码   |
| **"< 5 秒内循环"不可兑现**       | 实测单文件 ts-jest 启动 7~10 秒，全量 19 分钟；可兑现目标是"单文件 10 秒 / 全量 19 分钟" |

## 5. 优化措施

每项给出动作、落点、生效判据、收益、风险。工作量以人日计，均为开发机可完成部分。

### 措施 1（P0）建立可信本地门 —— 0.5~1 人日

- **动作**：新增 `scripts/test-local.mjs`：先按依赖顺序 build，再只跑 portable 用例，任一失败即非零退出。
- **落点**：`package.json` 增加 `test:local`；7 个包 `jest.config.js` 增加 portable/win-only 分组（命名约定 `*.win.test.ts` 或 `testPathIgnorePatterns`）。
- **生效判据**：删除全部 `dist` 后运行 `node scripts/test-local.mjs` 退出码为 0，且耗时记录在 `docs/STATUS_LOG.md`。
- **收益**：产品逻辑错的首次拦截点从 40 分钟降到 10 秒（单文件）/ 19 分钟（全量）。
- **风险**：分组可能误排真实 Win 行为用例。控制方式：win-only 用显式命名白名单，Win7 彩排仍跑全量。

### 措施 2（P0）清掉现存红灯 —— 0.5 人日

| 用例                                                           | 根因                                               | 处置                                                  |
| ------------------------------------------------------------ | ------------------------------------------------ | --------------------------------------------------- |
| `src/core/tests/a9-01-regression.test.ts:94`                 | 精确数组断言未跟上新增 `read_process_output`                | 改 `arrayContaining`，保留"不含 write/delete/shell"三条负向断言 |
| `src/gateway/tests/a9-r3-external-changes.test.ts:154`       | 同文件 `printf > file` 通过、`rm` 不生效，macOS Shell 语义差异 | 标 win-only，或改用 `fs.rmSync`                          |
| `src/workspace/tests/unit/a9-f2-baseline-safety.test.ts:167` | 22×1.9 MB 容量用例受磁盘与时限影响                           | 降规模到阈值边界，不进默认套件                                     |
| `src/workspace/tests/unit/a9-19-baseline-yield.test.ts`      | 572 秒性能用例                                        | 标 slow，默认不跑，只在性能门跑                                  |
| `src/runner` 偶发 1 红                                          | 复跑消失                                             | 记录 seed 与耗时，暂不修，观察 3 轮                              |

- **生效判据**：措施 1 的门在 macOS 上退出码 0，连续 3 次结果一致。

### 措施 3（P0/P1）夹具本地可预跑 —— 1~2 人日

- **动作**：把 `release/win7-product-v3/a9-batch2-smoke.cjs` 中"清理授权/拒绝判定"抽成纯函数，按「根路径 × 授权模式 × 拒绝集规则」建表驱动用例，在 macOS 直接跑。
- **落点**：新增 `validation/tests/a9-smoke-rules.test.*`；不改夹具对外输出结构。
- **生效判据**：把实现退化回 r96 状态（`CLEANUP_EXPIRES` 常量 + 到期条件），本地用例必须转红。这是该项唯一的验收方式。
- **收益**：p05 类"只在正式根触发"的失败本地拦下，每避免一次正式执行省约半天。
- **风险**：动验收代码本身。必须满足：只抽函数不改判定；用 golden 对比保证输出字节一致；须经 C14 授权与独立审核。

### 措施 4（P1）身份与拒绝集数据化 —— 1 人日

> **与既有任务书合并，不另立**：本条与 `docs/tasks/ENGINEERING_04_RC_ACCEPTANCE_TIME_REDUCTION.md` 的 E4-1（拒绝集移出执行工具字节）与 E4-2（驱动与夹具移出候选 ZIP）是同一命题。应并入该任务书执行，本文件不重复立项。该任务书当前为 `DRAFT_READY_FOR_REVIEW`，不授权实现。

- **动作**：候选 id、ZIP 哈希、拒绝集前缀移入单一 registry 文件，夹具与构建脚本读取它。
- **落点**：`release/win7-product-v3/` 新增 registry；`scripts/release/` 读取。
- **生效判据**：模拟 WIN7-55→WIN7-56，只改 registry 后 `--check-only` 通过，且 37/67 用例集不变。
- **收益**：身份变更从 29 文件 + 双构建降到 1 文件 + 一次构建复核。
- **风险**：ADR-0288 决定 6 限定"新设计照此执行，既有执行包在 RC 阶段调整"。只允许在新建包上实施，不回改已签候选。

### 措施 5（P1）治理分级 —— 0.5 人日（文档）

- **动作**：新增一条 ADR，明确两级：Level 1（安全模型、对外接口、持久化协议）走 ADR；Level 2（夹具参数、已知限制、环境说明）落 `docs/STATUS_LOG.md` 单条记录 + Release Note。
- **落点**：`AGENTS.md` §4/§8 增引用；`docs/DECISIONS.md` 新增一条。以 ADR-0288 为基线扩展，不改其结论。
- **生效判据**：下一轮只改夹具数据时，无新增 ADR，且 `node scripts/check_docs.mjs` 通过。
- **收益**：文档变更量目标从 25,501 行/26 提交降到 ≤1/3。
- **红线**：**不修改 C14 正文**，不设"放宽拦截"类豁免。

### 措施 6（P2）验收分级，但不改判据 —— 1 人日 + 合同修订

- **动作**：设 L1 冒烟（M1–M6 关键路径 + 启动，目标 ≤10 分钟）作为门 A 前的快速闸；L2 全量 37/67 仍是门 A/B 的唯一判据。
- **落点**：`docs/acceptance/ACCEPTANCE_AND_RELEASE_WORKFLOW.md` §7 增一节。
- **生效判据**：一次 L1 失败能在 10 分钟内给出失败用例号，且 L1 通过不得计入任何 PASS 结论。
- **收益**：夹具与环境错提前 30 分钟暴露。
- **风险**：合同修订，须负责人签。禁止把 L1 通过写成门 A 通过。

### 措施 7（P2）工作区与产物治理 —— 1 人日

- **动作**：`outputs/` 只保留证据 JSON、manifest 与报告；包体移出到仓库外归档；worktree 生命周期 ≤48 小时，脚本结束自动 `prune`。
- **生效判据**：`du -sh` 工作区 ≤8 GB，且 ADR-0286 绑定的 `f9ae2982` 证据目录逐文件仍在。
- **收益**：32 GB → 8 GB 以内。
- **风险**：`a9-39-w54-formal-packages` 9.1 GB 内含门 A 证据，**只能删包体，不能删证据**。清理须逐项记录，照 `e596c58` 的先例写一条 docs 记录。

## 9. 需要负责人裁决的事项

第一部分的四项：

1. **授权路径**：措施 1/2 要改 `scripts/`、`tests/`、`package.json`；措施 3 要改 `validation/`。当前无对应 APPROVED 任务书，需批准范围与分支。
2. **新增 ADR**：措施 5 的 ADR 分级，需明确是否以 ADR-0288 为基线扩展、是否同时修改 `AGENTS.md` §4 引用。
3. **合同修订**：措施 6 触及验收工作流 §7，属合同变更，需签字后才可起草。
4. **ENGINEERING_04 批准**：措施 4 已并入该任务书（E4-1/E4-2），需把其状态从 `DRAFT_READY_FOR_REVIEW` 推进到可执行。

第二部分的四项（变更更大，单独列出）：

5. **是否把 C14 从"按任务"改为"按风险域"**（§11.1）。这是唯一能消掉每轮固定税的改动，同时是安全模型变更，须以 ADR 签发。
6. **是否接受"产品身份 / 夹具身份"二元组**（§11.2）。若接受，须与 E4-2 合并审批，不能分两次改证据链。
7. **是否出具 Alpha 退出条件**（§11.10）。这决定后续所有提速是否有终点。
8. **是否允许先出证据账本设计、暂不实施**（§11.3）。只出设计的成本约半天，可避免 E4-2 落地后的返工。

## 11. 第二部分：体系与准则层（允许修改准则）

第一部分是"在现有规则下提速"。本节回答另一个问题：**如果把规则本身当作可改对象，全流程还有哪些结构性改进。** 每一项都标注要改哪些文件、由谁签。

### 11.1 授权模型：从"按任务"改为"按风险域"

- **现状**：C14 默认禁止实现，每次改动都要一份 APPROVED 任务书 + 路径白名单。先例已经存在：`docs/tasks/ENGINEERING_03_WIN7_DEV_CHANNEL.md` 是"按通道"的常设授权（r2 续期至 2026-11-28）。这说明"常设授权"在制度上可行，只是还没推广到实现代码。
- **改法**：把授权对象从"任务"改为"风险域"，边界写进 AGENTS.md §4：

| 域 | 范围 | 授权方式 | 事后要求 |
|---|---|---|---|
| A | `docs/**`、`tests/**`、`validation/**`、非交付脚本 | 常设授权，直接改 | 提交声明影响，`check_docs` 与本地门必过 |
| B | `src/**` 非安全路径（UI 文案、布局、日志措辞、非策略逻辑） | 常设授权 + 影响声明 | 本地门必过；一轮 DEV 彩排 |
| C | 安全模型、Policy、IPC schema、`native/`、打包与打包判据、ADR 正文、门 A/B 判据 | 逐次任务书 + 独立审核 | 不变 |

- **收益**：域 A/B 的前置治理从 2~4 小时降到 15 分钟内（2~4 小时为审计报告自述值，本次未独立计时，标 `UNKNOWN`）。高风险改动仍受同等约束。
- **代价与风险**：C14 是防自我扩权的属性，分域本身是安全模型变更，**必须由负责人签发 ADR**。同时域 C 应比现在更严——当前有测试改动未经独立审核就动了验收入口，这正是域 C 该收紧的地方。
- **优先级**：P1。它是其他改进的杠杆点；若要只做一件事，选这条。

### 11.2 身份模型：产品身份与夹具身份分离（并入 E4-2）

- **现状**：候选号同时表达"产品字节"和"夹具版本"。`ENGINEERING_04` 事实 F3 记录：WIN7-46→54 换发 8 次，其中 6 次未改产品非测试代码。每换一次都要双干净构建 + 两包改绑（总控 24 文件 + 补充 5 文件）。
- **改法**：候选身份拆成二元组 `(product_id, harness_id)`。`product_id` = hash(产品源码树 + native 工件 + 依赖)；`harness_id` = hash(`validation/**` + `release/win7-product-v3/**`)。门 A 报告与门 B 签发绑定二元组。改夹具 → `harness_id` 变、`product_id` 不变 → 不重做双构建，只做夹具自检 + 一轮 DEV。
- **收益**：F3 里 6/8 次的"纯夹具换发"从"换号 + 双构建 + 29 文件改绑"降为"改夹具 + 自检"。
- **代价与风险**：证据表述与门 B 签发格式要能表达二元组，属架构级变更；必须与 E4-2 合并审批，不能分两次改证据链。
- **优先级**：P1（RC 前）。

### 11.3 证据模型：从文件包改为可查询账本

- **现状**：一轮正式执行产出 197 个证据文件，`outputs/` 一级目录 18 个；核验靠人读 JSON，结论靠手写进 STATUS。
- **改法**：新增 `evidence/ledger.jsonl`（或 sqlite），每行 `(case_id, product_id, harness_id, run_id, verdict, artifact_sha256, host, timestamp)`。门 B 签发 = 对账本某区间的摘要签名 + 已知限制；人读的是由账本生成的报告视图。
- **收益**：① 核验从"读 197 文件"变成一条查询；② ADR-0112 的继承证据可机器判定（哈希相同即继承），不再人工声明；③ 门 B 的"已直接证明范围"可自动算边界。
- **代价与风险**：账本会成为唯一索引，必须有哈希链或签名防改写；迁移期双写。**不改变"只有 Win7 实机能产生 PASS"**——账本只是索引，不是证据来源。
- **优先级**：P2（RC 期）。设计要在 RC 前定，否则 E4-2 落地后证据链要返工一次。

### 11.4 状态模型：STATUS 改为结构化生成

- **现状**：`docs/STATUS.md` 是手写长文，最新记录堆在最前，当前含 23 条 `A9-39 r**` 修订；每轮都改同一个文件。本次会话期间就发生过三文件合并冲突的手工处理（提交 `56a8661` 的冲突解决说明）。
- **改法**：新增 `docs/status.json`（当前状态、当前候选、阻断项、最近 5 条事件）+ 生成器输出 `STATUS.md`；历史事件进 `STATUS_LOG.md`，只追加。
- **收益**：每轮不再改同一个长文件 → 并行会话冲突减少；`check_docs.mjs` 可校验机器可读部分；新会话读 JSON 而非 200 行散文。
- **代价与风险**：改的是全队入口文件，需一次全量迁移；生成器要进 `scripts/` 并有测试。
- **优先级**：P1（低风险、高确定性）。

### 11.5 ADR 压缩与退役

- **现状**：288 条 ADR、索引 288 行。定位一条现行规则要在 5,000 行里翻——本次为查 ADR-0288 就是这样做的。
- **改法**：**保留"正文不可改写"属性**。每累积 25 条做一次"合并章节"写入 `docs/ARCHITECTURE.md` 规范章节，索引标 `absorbed → 章节号`。日常读架构手册，深挖才回查 ADR。
- **收益**：新会话上下文成本从"扫 288 条"降到"读 10 章"；`AGENTS.md` §8 权威表可指向章节而非 ADR 编号。
- **代价与风险**：合并需人写；章节与 ADR 有歧义时以 ADR 正文为准，这条要写死。
- **优先级**：P2。

### 11.6 并行会话协作协议

- **现状**：本会话期间 `HEAD` 从 `f06e6db` 前进到 `6a93899`（治理合并），多会话并行已是常态，但没有书面协议。当前挂 3 个工作树、32 GB。
- **改法**：① 一会话一 worktree，分支名带会话前缀；② 每日两次固定合并窗口；③ 谁合并谁核验——合并者必须重跑本地门；④ 开工前由 `scripts/preflight.mjs` 检查 `HEAD` 漂移与 dirty。
- **收益**：消除"核验基线悄悄变了"的返工。本次核验必须标注"实测于 `f06e6db`，合并不涉及 `src/`"才成立，就是这个问题的直接体现。
- **代价与风险**：需要一个合并负责人，会引入等待；单人项目可退化为"合并前先 fetch 并记录基线段落"。
- **优先级**：P0（成本极低，写进 AGENTS.md §6 即可）。

### 11.7 环境前置体检（preflight）

- **现状**：HALTED 集中在固定位置——中继期 6 次彩排全部死在 R3 上传或 R7 回收（E4 事实 F5）；`r92` 续传 779 秒超时；`r96` 两次正式执行死在 p05；`r84` 首次彩排死在 R1 容量。失败代价 40 分钟到半天。
- **改法**：正式执行前跑 2 分钟的 go/no-go：目标机磁盘余量、当前登录会话归属（会话号会变，须现场重新发现）、DPI、进程基线与已知残留、网络吞吐（已有 50 KB/s 门槛）、拒绝集完整性、时间窗（M5 截止）。
- **收益**：F5、`r84`、`r92` 这类失败能在 2 分钟内判死，不必跑到第 40 分钟的 R3。
- **代价与风险**：preflight 自己也会漂移，其结论必须写入 run 证据；不得用它替代阶段内检查。
- **优先级**：P0，与第一部分措施 1 同批做。

### 11.8 缺陷逃逸台账

- **现状**：WIN7-33 是产品缺陷逃到实机才暴露（`app.disableHardwareAcceleration()` 在 ready 之后调用，仅 Windows 触发），之后补了 `a9-startup-window.test.ts`。这是一次性补救，不是制度。
- **改法**：每次逃逸登记三项：发现层级、若早一层能否发现、补的用例路径；度量逃逸率 = 逃逸数 / 变更数。
- **收益**：把"为什么本地没拦住"变成可统计的问题，而不是每轮重新争论要不要建 Mock。
- **代价与风险**：需要持续记录，容易烂尾；挂在 `STATUS_LOG.md` 新小节即可，不新建体系。
- **优先级**：P1。

### 11.9 发布自动化与回滚

- **现状**：ADR-0287 记录的发布是手工步骤（推分支、推 tag、建 Release、传 ZIP 与 sha256）。
- **改法**：`scripts/release/publish.mjs`：读 `release-manifest.json` → 校验 ZIP 哈希与 tag 绑定 → 幂等创建/更新 Release → 写发布记录。配套 `rollback.mjs`（撤 Release 标 yank，不删 tag）。
- **收益**：发布从易错手工变可重复命令；回滚有预案。
- **代价与风险**：涉及外部写入，须绑定具体目标与授权；幂等逻辑要防重复上传同一 ZIP。
- **优先级**：P2。

### 11.10 Alpha 退出条件与特性冻结

- **现状**：`docs/STATUS.md` 反复写"完整 Alpha 2/RC 未签"，但没有书面条件说明何时算走出 alpha。
- **改法**：在 PRD 或新 ADR 定义退出条件：① 能力清单全部有 Win7 实机证据（Full Access / Read Only / Review fail-closed）；② 已知限制台账化并签发；③ 连续 2 轮零产品缺陷逃逸；④ §15 指标达标。达成就冻结特性，只修缺陷。
- **收益**：全流程最上游的一条。没有它，前文所有提速只是让"永远在做 alpha"这件事更快。
- **代价与风险**：需负责人拍板能力边界；可能与"alpha 内快速迭代"偏好冲突，应写明 alpha 内仍可加特性、只是要记账。
- **优先级**：P0（决策成本最低，收益最长期）。

### 11.11 EOL 组件供应链台账

- **现状**：Electron 22.3.27、Node 16.17.1、Chromium 108、MinGit 2.46.2 全部 EOL，不再有安全补丁。风险靠"不联网 + Restricted Token + 输出上限"缓解，但没有到期评估。
- **改法**：`docs/WIN7_CONSTRAINTS.md` §6 增加"CVE 台账与缓解说明"列，每季度评估一次，登记各组件 EOL 日期与替代路径（降级阶梯已由 ADR 定义）。
- **收益**：把"知道它 EOL"变成"有台账、有到期动作"；审计可答。
- **代价与风险**：评估无法自动化；台账不更新会变形式主义，建议只写"变化时更新"，不设固定仪式。
- **优先级**：P2（持续）。

## 14. 不可动清单

以下七条任何情况下不建议修改，改了会让"通过"失去意义：

2. **证据分层与状态词**（`docs/GLOSSARY.md`）的含义不得为了好看而放宽。
3. **私钥红线**：不读取、不输出、不进 worktree。
4. **Accepted ADR 正文不可改写**，只能新增或标 Superseded。
5. **门 A/B 判据**（11 阶段 / 37 用例 / 67 断言）不得由执行方自行删减。
6. **C14 的域 C 部分**保持逐次审批。
7. **输出上限、进程树回收、凭据脱敏、TLS 默认验证** 不得因提速而降级。
