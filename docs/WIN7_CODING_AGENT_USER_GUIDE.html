📖 产品定义与设计哲学

Win7 Coding Agent 是专门面向 Windows 7 SP1 x64 遗留系统与受限企业内网环境打造的对话式 Coding Agent 执行端与客户端。

为什么选择 Agent-First 而非传统 IDE 插件？

在工业制造、银行内网及专用设备等大量 Windows 7 场景下，缺乏现代 VSCode/Docker 运行条件。本产品采用“对话即工作区、低视觉噪声、按需检查、准备区审批”的 Agent-First 架构，无需复杂配置，开箱即用。

核心分层架构模型

💻 Win7 本地客户端 (Workbench)

  • UI 交互端: 极简三栏布局，低内存占用，兼容 Win7 GDI/DWM 渲染。
  • 只读代码查看器: 支持代码跳转、高亮与选区上下文提取。
  • Review 准备区: 多文件差异比对与逐文件审核。

🛡️ 本地安全执行引擎 (Host/Core)

  • 只读工具链: 安全读取代码、Grep 搜索、Git 历史状态分析。
  • 受控 Runner: 结构化 argv 执行非交互测试，超时与进程树回收。
  • 不可变 SQLite 账本: 完整审计追踪所有事件与决策。

三大核心设计原则

  1. 对话中心 (Agent-First): 开发者无需理解复杂的底层 harness 或 lease 概念，通过自然语言描述需求，Agent 主动规划、检索与验证。
  2. 多文件准备区 (Staging Area): Agent 对代码的任何修改提议首先在私有准备区生成，不直接触碰用户真实工作区。
  3. 精确一次性审批 (Explicit Approval): 只有在用户完成 Diff 审查并点击“应用变更”后，才通过原子写入生效，并支持一键故障回滚。

🚀 3 分钟极速上手指南

只需三步，即可在 Win7 环境中开启智能结对编程：

第一步：选定工作区与配置

启动客户端后，点击左上角 “选择本地工作区”，选定待维护的代码目录。点击左下角 ⚙ 设置确认连接模式（支持离线 Replay、内网 Gateway 或 DeepSeek）。

第二步：自然语言描述需求

在底部输入框输入要完成的任务（如 “排查 parser.c 中的内存泄漏并编写单元测试”），选择 “直接做” 或 “先计划” 模式后按 Enter 发送。

第三步：Review 审核与一键应用

Agent 分析并执行完毕后，点击右侧 Review 准备区 查看文件变更 Diff。逐文件确认后点击 “应用已接受变更”，修改立即安全写入。

⚠️ Win7 专属注意事项

产品原生支持中文路径、空格路径及 GBK/CP936/UTF-8 各种编码格式。严禁在未经受控审批前手动跨进程修改正在执行任务的目标文件。

💡 12 条核心用户旅程全景手册

# 用户旅程 (User Journey) 交互触发与核心逻辑 安全与确定性保障
J1 自然语言极速启动 直接在输入框输入任务按 Enter 提交，系统自动创建会话并启动流式回答 无需理解底层 harness/lease 术语
J2 先计划模式与任务拆解 切换“先计划”，Agent 首先给出 4 步规划（目标/拟修改/验证/风险） 必须用户点击“批准计划”后才调用工具
J3 上下文精准引用 通过 @文件、目录、代码查看器选区或文本附件注入上下文 有界预算控制（单轮≤24项，≤64KB）
J4 连续流式消息聚合 连续 gateway.delta 自动合并为自然消息段，支持 Markdown 与代码块 原始事件账本保真，展示层无感连续
J5 工具卡片折叠与交互 只读读取、Grep 检索以紧凑卡片展现，显示耗时与状态 只读工具零写入风险，可随时展开
J6 多文件 Review 准备区 修改提议保存在私有 Blob 暂存区，右侧 Unified Diff 红绿高亮显示 用户可逐文件标记“接受”或“拒绝”
J7 一次性审批与原子写入 生成绑定 SHA-256 哈希的一次性审批 Token，点击“应用”原子写入 自动备份基线，写入或验证失败立即回滚
J8 真实 Runner 验证闭环 非交互式执行自动化测试命令，输出回显在 Review 验证卡片中 结构化 argv 传参，无 Shell 拼接注入
J9 长任务取消与原地重试 运行中提交按钮变为红色“■ 停止”，点击即刻中断；失败卡片提供原地“重试” 中断不丢失上下文与暂存区
J10 多会话与 Goal 状态恢复 左侧会话独立切换，Goal 状态原子更新，异常重启自动标记 INTERRUPTED SQLite WAL 保证跨重启零损坏
J11 Terminal/Browser 边界隔离 Terminal 与 Browser 保持禁用，禁止模型向交互终端注入按键 遵循 ADR-0027/0075 严格防御边界
J12 诊断中心与不可变审计 打开 ⌁ 诊断抽屉，实时查看 EventEnvelopeV2 账本与 Runner 原始日志 64KB 单事件上限，序列缺口严密监控

🛡️ 四道安全防线与能力边界

本项目严格遵循 AGENTS.md 与 WIN7_CONSTRAINTS.md 最高安全红线：

防线 1：桌面 Renderer 零权限隔离

UI 渲染进程严格禁用 Node 继承与直接文件系统操作，所有数据交互必须经过 Schema 强校验的 IPC 通道，彻底杜绝 XSS 越权。

防线 2：非交互式 Runner 超时与隔离

测试与验证命令采用结构化 argv 传参，严禁拼接执行未经审查的 Shell 字符串。配备独立超时控制与 Windows 进程树销毁机制。

防线 3：凭据 Windows DPAPI 加密

所有 Gateway API Key 均调用 Windows 底层 DPAPI (CryptProtectData) 进行当前用户凭据加密，禁止明文写入数据库或日志。

防线 4：Terminal 与 Browser 严格边界

明确禁止模型向交互终端注入不可控键盘按键或控制序列；禁止内置过时浏览器访问不受信任的公网页面。
