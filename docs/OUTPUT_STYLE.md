# 面向负责人的输出规范

依据：ADR-0190。目标：让负责人用更少时间读懂结论、看清依据并作出裁决。
本规范只约束**写给人读**的输出形式，不授予实现、构建、远端操作或发布权限，不改变任何合同判据。

## 0. 适用范围

| 适用 | 不适用 |
|---|---|
| 给负责人的回复、进展汇报、待裁决材料 | 机器读取的格式：JSON 证据、`status/latest-validation.json`、任务书元数据字段 |
| `reports/` 新报告；任务书、ADR、STATUS 中新写或修改的段落 | 历史报告与既有段落（不回改） |
| 为解释而生成的图和 HTML 页 | Accepted ADR 正文（不得改写） |

状态词和流程名词以 [GLOSSARY.md](GLOSSARY.md) 为准。

## 1. 受控中文写作规则

规则借鉴 ASD-STE100 的思路，按中文调整。引用时写编号，如“OUTPUT_STYLE W04”。

| 编号 | 规则 |
|---|---|
| W01 | 先写结论，再写依据。第一句给出结论，或给出需要负责人裁决的问题。 |
| W02 | 一句只说一件事。步骤句目标不超过 30 字，说明句目标不超过 45 字；超出时拆句。 |
| W03 | 操作步骤用祈使句，每步一个动作，按顺序编号。 |
| W04 | 状态词、流程名词只用 GLOSSARY 中的写法。同一事物全文只用一个名称；不自造缩写。编号首次出现时附一句说明。 |
| W05 | 不用模糊程度词：基本、应该、大概、差不多、理论上、预计通过。改写为确定事实，或标 `UNKNOWN`、`NOT_PERFORMED`、待验证。 |
| W06 | 每个结论写明证据层级（开发机 / Win10 验收机 / Win7 实机）和绑定的候选或提交。 |
| W07 | 写明执行者：负责人、执行代理或独立审核。不用“已被处理”这类无主语句。 |
| W08 | 范围写完整。不用“等”结尾隐藏范围；有排除项时写“不包括 X”。 |
| W09 | 括号嵌套不超过一层。哈希写前 8 位加 `…`，完整值放在链接的报告中。 |
| W10 | 一段只讲一个主题。三个以上并列条件或对比项改用表格。 |
| W11 | 待裁决材料按“问题 → 选项 → 每个选项的影响 → 推荐及理由 → 一句明确的提问”组织。 |
| W12 | 不复述已有文档，写编号或链接（CLAUDE.md 规则 6）。 |

改写示例（W02、W04、W06）：

> 改写前：A9-26 第一批经 WIN7-42 W42-23、补充真实 Windows Git R0-01～04 及门 B 收尾确认，恢复目录误暂存问题已关闭。
>
> 改写后：恢复目录误暂存问题已关闭。证据是 WIN7-42（第一批可靠性候选）的 Win7 实机 W42-23 项和补充 Git 检查 R0-01～04，负责人已在门 B 签发。

## 2. 图解

下列内容优先给图，再给文字：

- 跨三个以上组件的调用链或数据流（如 Renderer → IPC → Core → Runner）。
- 状态迁移（如任务书状态、候选从冻结到门 B）。
- 时间演进（如候选换发序列、ADR 取代关系）。
- 选项对比（如待裁决方案的影响面）。

Markdown 文档内的图用 Mermaid 代码块，便于 diff 和审阅。图只表达正文已有的事实，不单独引入新结论。

## 3. HTML 页面

| 类型 | 用途 | 位置 |
|---|---|---|
| 演示 / Demo | 构建或上机前确认方向，用真实渲染代码加桩数据 | 任务书指定位置，通常为 `plans/<任务>-demo/` |
| 解说材料 | 解释任务、ADR 区间、验收结果或待裁决事项 | 默认写入 `outputs/`（已被 Git 忽略），用完可丢弃 |

规则：

1. 页面顶部固定写明：“解说材料，非事实来源，非验收证据”（Demo 写“演示，非验收证据”），以及生成日期和依据的提交哈希。
2. 页面内容只来自仓库内的 Markdown、任务书、ADR 和报告，每个结论附来源链接。与 Markdown 不一致时以 Markdown 为准。
3. 单文件、自包含，不引用外部网络资源；UTF-8 无 BOM、LF。
4. 负责人要求留存时，才放入 `reports/YYYY-MM/` 并在 [reports/README.md](reports/README.md) 登记。

## 4. 生成与渲染的边界

生成 HTML 或图解文件，不等于启动浏览器、GUI、截图或渲染核对。
AGENTS.md §6、§7 的渲染限制继续有效：只在负责人要求，或交付物本身是 UI/视觉产物时，才做渲染核对。

## 5. 自动加载与机器检查

依据 ADR-0191：

- 核心五条（W01、W02、W04、W05、W06）同时写在 AGENTS.md §7 和 CLAUDE.md，随 Agent 入口自动加载。完整规则以本文件为准。
- `npm run docs:check` 对 `docs/reports/` 下日期不早于 2026-10-06 的报告检查 W05 词表，见 [DOCS_05](tasks/DOCS_05_REPORT_VAGUE_WORDING_CHECK.md)。
  代码、`>` 引用行和中文引号内的原文引用不检查。词表之外的模糊表达仍靠人工审阅。

## 6. 不采用的形式

解说视频暂不采用：生成成本高，且在 Win7 交付链路上没有对应需求。需要时另行裁决。
