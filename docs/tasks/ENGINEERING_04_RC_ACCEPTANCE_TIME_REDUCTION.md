## 3. 建议条目

### 3.1 E4-1 拒绝集移出执行工具字节（原建议 4）

- 现状：拒绝集写在 `rehearsal-gate.cjs` 的 `FORBIDDEN_PREFIX_SHA256` 数组和 3 个测试文件里（F2）。
- 方案：拒绝集保持只增不减，改为门 A 授权哈希绑定的数据文件。工具只校验“本次 run 不在集合内”与“集合未缩减”。
- 收益：新增一个已用 run 不再改工具和测试，F2 这类整轮消失。
- 风险：数据文件被删项即可复用旧 run。对策：授权绑定数据文件 SHA，并校验新集合是旧集合的超集。
- 需要：新 ADR（改动防重放机制的载体，属安全模型）。
- 验收：新增一项后 `execution_tools_sha256` 不变，测试文件无改动；删一项时预检失败。

### 3.2 E4-2 驱动与夹具移出候选 ZIP（原建议 5）

- 现状：`validation/` 下的驱动与夹具随产品 ZIP 打包，驱动一改即换发候选（F3）。
- 方案：驱动与夹具组成“验收套件”，单独构建、单独计算哈希；门 A 授权同时绑定候选 ZIP 哈希与套件哈希。
- 收益：驱动修正不再换发候选，F3 中 6 次换发可省。
- 风险：产品双干净构建不再覆盖套件。对策：套件自身做双干净构建并逐字节比对。
- 需要：新 ADR（候选身份与包结构）；检索 `docs/DECISIONS.md` 未找到要求驱动入包的 ADR，是否存在：UNKNOWN（Q2）。
- 验收：只改驱动时候选 ZIP SHA 不变；套件两次构建同字节；授权缺任一哈希即拒绝。

### 3.3 E4-3 彩排使用正式目录布局（原建议 6）

- 现状：彩排根与正式根不同，候选代码按根路径分支，正式分支从未在彩排中执行（F4）。
- 方案：彩排与正式执行使用同一远端根模板、同一账户与同一模式开关，只差授权签名与证据类别。代码中按“开发/正式”分支的判断只允许出现在授权与证据类别上。
- 收益：彩排 PASS 能预测正式结果；F4 这类问题在彩排阶段暴露。
- 风险：彩排写入正式根模板目录，须保证 run 隔离与收尾清理。对策：沿用每 run 独立子目录与 R8 收尾检查。
- 需要：新 ADR（ENGINEERING_03 §7 根外禁止与常设授权范围需调整）。
- 验收：静态检查列出全部按根路径或模式分支的代码点，除授权与证据类别外为零；彩排与正式的远端根模板字符串一致。

### 3.4 E4-4 不可变大件预置到目标机（原建议 7）

- 现状：每次执行在 R3 重新上传候选 ZIP 等大件；中继期间失败集中在 R3、R7（F5）。
- 方案：候选 ZIP 等不可变大件按内容哈希预置到目标机缓存；执行时只核对哈希，不重传。
- 收益：R3 上传不受链路影响；同一候选的重试不重传大件。
- 风险：核对后、使用前文件被替换。该风险与“上传后再使用”相同；对策为使用前再次核对哈希并只读打开。
- 需要：新 ADR（证据链与目标机写入范围）；缓存目录的权限、配额与清理归属待定（Q4）。
- 验收：同一候选第二次执行上传候选 ZIP 字节数为 0；缓存文件哈希不符时执行停止。

### 3.5 E4-5 两包共用传输与编排层（原建议 8）

- 现状：总控包与补充包各有一份续传、超时与拒绝集校验代码（F6）。
- 方案：抽成一份公共模块，两包引用同一字节。
- 收益：同类缺陷只修一次，审核也只做一次。
- 风险：公共模块一改，两包同时受影响。对策：公共模块独立版本号与合同测试，两包授权各自绑定其 SHA。
- 需要：本任务书批准即可；不改安全模型时不需新 ADR。
- 验收：两包传输层文件 SHA 相同；修一个续传缺陷只改一个文件。

### 3.6 E4-6 审核分级（原建议 9，依赖 E4-1）

- 现状：只改数据的轮次与改逻辑的轮次走同样的独立审核（F2）。
- 方案：只改数据的轮次（run 编号、主机地址、拒绝集）由自动校验确认“只有声明字段变化”，不另做独立审核；改逻辑的轮次保留独立审核。
- 收益：数据类改动当轮可用，不等审核。
- 风险：数据改动夹带逻辑改动。对策：自动校验按文件与字段白名单比对，出现白名单外差异即升级为独立审核。
- 需要：新 ADR（审核规则）；判定执行者待定（Q5）。
- 验收：构造一个夹带逻辑改动的数据轮次，自动校验判为需要独立审核。
