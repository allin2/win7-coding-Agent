# Win7 Coding Agent — Agent-first 产品需求合同 v1

Status: `OWNER_CONFIRMED`

Confirmed-At: `2026-08-20`

Target-Version: `0.2.0-alpha.1` → `0.2.0-rc.1`

Source-Task: `docs/tasks/A8_AGENT_FIRST_PRODUCT_EXPERIENCE.md`

## 1. 产品定义与成功指标

Win7 Coding Agent 是面向 Windows 7 项目开发者的对话式 Coding Agent，不是验收控制台，也不以
重建完整 IDE 为 MVP 目标。用户用自然语言描述目标，产品围绕同一会话完成工作区理解、结构化计划、
代码读取、受控修改、测试验证、Diff Review、失败恢复与审计。

Codex 与 ZCode 只作为交互模型参考：学习对话优先、低视觉噪声、Goal、工具卡片、Review 与按需上下文
面板，不做像素复制，也不继承其未在 Win7 上验证的权限或隔离假设。

首要成功指标：新用户在三分钟内选择项目、输入需求并看到 Agent 开始工作，不需要理解 harness、lease、
固定场景、State 序号或内部事件协议。

## 2. 核心交互合同

1. 选择工作区后直接进入会话；一个工作区允许多个会话，每个会话同一时间只运行一个前台任务。
2. `Enter` 提交，`Shift+Enter` 换行；任务运行时主操作变为“停止”，失败后在原位置提供重试。
3. 支持“直接执行”和“先计划”两种模式。计划必须列出目标、拟读取/修改文件、验证方式与风险。
4. 固定场景不再是任务前置：可复用内容转为提示词模板，验收场景只存在于 Diagnostics 开发者区域。
5. 连续 `gateway.delta` 必须按任务与 request ID 合并为 Assistant 消息；原始事件只进入诊断与审计。
6. 计划、文件读取、搜索、Runner、测试、审批与错误显示为可折叠卡片；默认只显示状态、耗时和摘要。
7. 可恢复错误不得清空对话、Goal、工具结果或准备中的 Diff；连续失败后暂停并交还用户决定。

## 3. 信息架构

- 左侧：工作区、会话和 Goal。
- 中间：用户/Assistant 连续对话、结构化计划和工具卡片。
- 右侧：按需显示代码、文件引用、变更 Diff 与验证结果。
- 工作区标签：`Agent / Review / Terminal / Browser`。
- 全局入口：`Settings / Diagnostics`。

Gateway URL、CA、API Key、模型底层参数、验收状态和协议字段不得占用日常任务主界面。主界面只显示
当前模型、连接状态和用户可采取的动作。

## 4. 上下文、代码与变更

- 支持 `@文件`、`@目录`、文件面板“加入上下文”和文本附件；图片附件不属于首个 MVP 增量。
- 显示本轮实际使用的文件，不默认把完整仓库加载进模型上下文。
- 右侧只读代码查看器提供行号、高亮、搜索、跳转，以及从选区发起解释/修复/加入上下文。
- Agent 先形成多文件准备区；Review 按文件展示新增、修改、删除、统一 Diff、测试结果和未验证项。
- 用户可逐文件接受或拒绝；批准后才写入正式工作区。MVP 不提供 Diff 内直接编辑。

## 5. Runner、Terminal 与 Browser

- 读取、搜索和登记的低风险非交互测试可自动执行；Runner 继续使用结构化 argv、关闭 stdin、超时、
  输出上限、进程树回收、审计与既有 D-013 Profile。
- 用户 Terminal 与 Agent Runner 必须能力隔离。模型不能注入输入、按键、粘贴或控制序列。现有
  `NO_GO_INTERACTIVE_WINPTY` 结论保持有效；A8 的 Terminal 实现必须另行设计并通过 Win7 门槛，
  不得把旧 winpty 包装成已支持能力。
- Browser 只支持可信本地预览、用户显式打开系统浏览器和管理员登记的内网目标；不得接管用户浏览器，
  不得把 Electron 22 当作任意不可信网页的安全边界。

## 6. 会话、Goal 与恢复

- 保存工作区、会话、对话、Goal、计划步骤、文件引用、工具摘要、验证和 Review 状态。
- 应用异常退出后把未完成任务标记为“已中断”，不得自动继续执行。
- 恢复准备中的 Diff 时重新验证工作区基线哈希；漂移即 fail-closed 并要求重新计划。
- API Key、授权头和凭据不得写入普通会话数据库、聊天、命令行、报告或工作区文件。
- 旧 `0.1.0-rc.1` 验收会话只读归档；新版本只迁移工作区列表和安全设置。

## 7. MVP 包含与非目标

MVP 必须形成完整闭环：工作区、多会话、自然语言输入、直接/计划模式、连续流式回答、上下文引用、
只读代码查看器、工具卡片、多文件 Review、低风险 Runner、测试、恢复、隔离 Terminal、受限 Browser、
Settings 和 Diagnostics。

以下明确不在 `0.2.0` MVP：完整代码编辑器、Agent 控制的交互终端、任意 Shell、Git 写操作、多 Agent、
后台并发任务队列、任意浏览器自动化、插件市场、自动更新、无审批完全自主模式、未登记模型和高风险
Runner Profile。Git 只允许经专用适配器提供状态、Diff 与历史等只读能力。

## 8. 版本、交付与验收

- `0.1.0-rc.1` 永久冻结为已验证技术基线；A8 不原地改包、不覆盖其标签、证据或长期归档。
- A8 开发版本为 `0.2.0-alpha.1`，完成开发机、Win10、Win7 三层门禁后才可形成 `0.2.0-rc.1`。
- 新旧版本使用独立目录、用户数据与版本标识并行安装；新版本完整 PASS 前保留旧 RC 回退能力。
- 新候选必须产生新哈希、manifest、SBOM、许可证闭包、证据和唯一 Win7 租约；既有原生组件 PASS
  只构成输入资格，不自动构成 A8 产品 PASS。

十二条真实用户旅程是硬门槛：自然语言启动、计划、上下文引用、连续消息、工具卡片、多文件 Review、
真实测试、原地恢复、重启恢复、Terminal/Browser/Settings/Diagnostics 边界、Win7 生命周期零残留、
以及普通开发者不接触验收术语即可完成任务。单元测试或 harness PASS 不能替代产品旅程。
