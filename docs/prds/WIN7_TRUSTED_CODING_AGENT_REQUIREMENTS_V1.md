本合同由产品负责人通过连续 GrillMe 设计审查确认。它定义 A9 的唯一产品需求基线，目标是在
Windows 7 SP1 x64 上快速交付一个现实可用的 Coding Agent，而不是把旧平台包装成不存在的强安全沙箱。

A8 `0.2.0-alpha.1` 的 Review-first 合同、候选和证据保持历史有效；A9 复用其代码与经过验证的运行时输入，
但不继承 A8 的产品 PASS，也不继续沿用阻塞 Coding Agent 日常工作的默认权限模型。

## 1. 产品定义

### A9-P01 一句话定义

A9 是面向企业内部受信开发环境的本地优先 Coding Agent：模型运行在用户配置的内网或远程
OpenAI-compatible 服务，Win7 客户端负责项目理解、文件管理、代码修改、Shell、测试、Git、状态恢复与审计。

### A9-P02 首要目标

用户选择工作区和模型后，应能用自然语言完成以下闭环：

1. 阅读陌生项目并给出有文件依据的解释；
2. 定位并修复真实缺陷；
3. 实现涉及多个文件的小功能；
4. 运行测试或构建并根据失败继续修复；
5. 查看 Diff、撤销本轮修改并在重启后继续任务。

### A9-P03 设计取向

- 现实可用性优先于强安全承诺；用户负责在可信工作区、账号和网络环境中使用 Full Access。
- 不把 Win7 的 Restricted Token、Job Object、ACL 或 `taskkill` 描述为现代沙箱。
- 安全机制用于减少误操作、保留证据和支持恢复，不应让大多数正常 Coding 任务处于不可用状态。
- 本地能力默认直接工作；远程执行只是可选补充，不是普通 Shell、Git 或文件写入的前置。

## 2. 信任模型与权限模式

### A9-M01 三种模式

| 模式 | 默认行为 | 适用场景 |
|---|---|---|
| Full Access | 当前 Windows 用户可做的本地操作默认可由 Agent 执行 | 用户确认可信的日常开发工作区；推荐默认 |
| Review | Agent 准备变更，用户在写入或高影响操作前复核 | 不熟悉项目或希望逐步检查 |
| Read Only | 只允许读取、搜索、分析和无副作用探测 | 审查、解释或敏感项目 |

首次打开工作区必须展示模式选择并推荐 Full Access；确认后记住工作区设置。模式切换进入审计，
Read Only/Review 的约束不能被工作区文件或模型文本覆盖。

### A9-M02 Full Access 权限

- 使用启动客户端的当前 Windows 用户权限，不创建虚构的沙箱身份。
- 允许工作区内外绝对路径；工作区外目标必须在 UI 和审计中醒目标识，但不额外审批。
- 允许项目脚本、包管理器、项目依赖安装、Git hooks、filters、helpers 和用户已有工具按真实环境工作。
- 不自动提权；注册表、服务、系统级/全局依赖、系统配置和管理员操作必须由用户确认并在外部完成或显式授权。
- 项目依赖安装可自主执行，但必须使用项目现有包管理器并保留 manifest/lockfile 变化。

### A9-M03 始终确认的操作

即使在 Full Access，下列操作也要求绑定可见目标的一次性确认：

- `git push`、force push、删除远端分支；
- 发布、部署、上传、发表评论、创建 PR 等外部写操作；
- 永久删除、批量删除和明确不可恢复的覆盖；
- `git reset --hard`、`git clean`、强制切换覆盖、删除分支等破坏性 Git 操作；
- 提权、系统级安装、注册表/服务/系统配置修改。

这是尽力而为的行为策略，不宣称能从任意 Shell 字符串中完美识别所有外部副作用。审批必须绑定
完整可见操作；目标、参数或计划变化后旧审批失效。

## 3. Agent 工具合同

### A9-T01 Alpha 1 工具面

模型可见的首批工具统一采用简短、稳定名称：

- `list`：列目录；
- `read`：分段读取文本或识别文件类型；
- `search`：按文件名或文本搜索；
- `write`：创建或完整写入文件；
- `edit`：精确替换或补丁式编辑；
- `copy`、`move`、`delete`：文件管理；
- `shell`：运行当前 Windows Shell 命令；
- `update_plan`：大任务更新可见计划。

Alpha 1 使用顺序工具调用。托管后台进程可以在后续工具调用期间继续运行，但模型同一时刻只发起一个新工具调用。

### A9-T02 文件工具优先

修改源码优先使用 `edit/write`，因为它们能保持编码、生成 Diff 并建立 checkpoint。Shell 重定向、
PowerShell cmdlet 和项目脚本仍被允许；系统必须观察最终文件变化并纳入同一审计、Diff 与恢复链路，
不能因来源不同而失去撤销能力。

### A9-T03 工具调用正确性

- 每个工具使用严格 JSON Schema，拒绝未知字段和畸形参数。
- 文件写入绑定读取时的内容哈希；基线变化时停止、重新读取并重新计算。
- 工具输出是数据，不获得改变权限、指令优先级或工具目录的能力。
- 所有失败返回结构化错误、可采取动作和真实状态；禁止静默吞错。

## 4. Shell 与进程执行

### A9-SH01 Shell 选择

选择顺序为：工作区显式设置 → Windows PowerShell 5.1 → `cmd.exe`。

- WMF/PowerShell 5.1 是推荐前置，不是应用启动硬门槛，也不随 Alpha 1 包自动安装。
- PowerShell 2～4 仅提供 Best Effort；默认降级到 CMD，用户可以手工强制选择。
- Git Bash 是用户可选项，不因 MinGit 存在而假设可用。
- 当前 Shell、版本、编码和工作目录必须进入模型上下文与工具卡片；不做 PowerShell/CMD 自动翻译。

PowerShell 5.1 使用 `-NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand`
调用，命令按 UTF-16LE Base64 传输，并显式归一化 `$LASTEXITCODE`。源码写入继续优先走文件工具，
避免 Windows PowerShell 5.1 不一致的重定向编码行为。

### A9-SH02 通用命令语义

- `shell` 接受完整命令文本，包括管道、重定向、条件、项目脚本和当前 Shell 的正常语法。
- 每次普通调用使用独立进程；`cwd` 和环境覆盖显式传递。需要共享 Shell 状态时在同一调用中组合命令。
- 默认继承当前用户环境并叠加工作区设置；Agent Provider 凭据不自动注入 Shell。
- Agent Shell 关闭 stdin；遇到交互提示时要求模型改用非交互参数。
- 不设置任意、固定且很短的命令硬超时。Runner 提供连接/启动边界、软时长提示、用户取消、输出上限、
  进程树终止和可选任务级 deadline。
- 用户取消时先温和终止，再强制清理已知进程树；无法证明清理完成时显示可能残留，不能虚报成功。

### A9-SH03 托管后台进程

- 支持最多三个默认可配置的开发服务器、watcher 等托管后台进程，返回句柄并允许轮询增量输出和停止。
- 应用崩溃或重启后不自动重放；记录命令/PID并探测旧进程，由用户决定。
- 关闭应用时可以“停止受管进程后退出”或“将进程留给系统后退出”；Agent 自身不进入托盘或后台常驻。

### A9-SH04 网络与输出

- Shell 继承机器本身的网络、代理、证书和可执行工具能力，不设置域名白名单。
- `curl` 等工具不是 Win7 自带前置；不存在时按可选能力降级。
- 完整 stdout/stderr 原始字节保存在本地有界日志中；送入模型和 UI 前过滤危险控制序列、限制单行和预览大小，
  同时保留可理解的 ANSI 颜色语义。
- 不因输出截断丢失退出码、截断原因、日志路径和进程清理状态。

## 5. 文件、Diff、Checkpoint 与恢复

### A9-F01 文件范围

- Full Access 允许读写当前用户有权访问的路径，工作区外路径醒目标识。
- Junction、symlink、mount point 解析真实路径并防止递归环。
- 默认遵循 `.gitignore`，额外内置忽略 `.git`、依赖缓存和构建产物，并支持项目级 `.agentignore`。
- 用户明确指定被忽略目标时允许覆盖。

### A9-F02 编码与大文件

- 保持原编码、BOM、CRLF/LF 和末尾换行；新文件默认 UTF-8 无 BOM，并遵循项目配置。
- 正式覆盖 UTF-8、UTF-16、CP936、中文/空格/盘符/UNC 和接近 `MAX_PATH` 的适用场景。
- 无法可靠解码时拒绝文本编辑，但允许二进制复制、移动或删除。
- 大文本按段读取；二进制先识别类型再路由专用工具，超过阈值提示而非让客户端崩溃。

### A9-F03 写入与撤销

- Full Access 直接写正式工作区；Review 继续使用准备区；Read Only 禁止写入。
- 每轮建立文件级 checkpoint，记录修改前哈希和可恢复内容；不依赖 Git 仓库。
- 写入使用临时文件、原子替换和写后校验；失败保留恢复清单。
- 用户可以按文件撤销本轮变化；删除默认进入回收站或产品恢复区，永久/批量删除始终确认。
- Shell 或外部程序造成的变化采用轮前/轮后基线发现并纳入 Diff；不能可靠恢复时明确标记。

## 6. Git

### A9-G01 混合 Git 模型

- Git 状态、Diff、分支和历史展示继续复用结构化 Git Adapter。
- Trusted Full Access 允许模型通过 `shell` 使用真实 `git` 命令，不再强制隔离 system/global/repository 配置。
- 用户的 hooks、filters、textconv、pager、credential/SSH helper 和已有认证环境可以正常生效，并在 UI 提示仓库存在外部执行机制。
- 产品不自行托管 Git 密码、Token 或 SSH Key。

### A9-G02 操作策略

- `fetch` 可自主执行；`pull` 在 Full Access 下可自主执行，但先建立 checkpoint 并显示远端/分支。
- 分支、add、stash、merge、rebase 等本地写操作可按任务执行；只有用户明确要求时才创建 commit。
- push、force push、远端删除和外部平台写操作始终确认。
- 非 Git 工作区拥有完整 Agent 能力；只有用户明确要求时才执行 `git init`。
- 子模块、Git LFS、`gh`/`glab` 和大型仓库高级工作流为 Best Effort，不作为 Alpha 1 硬门槛。

## 7. 模型 Gateway

### A9-GW01 OpenAI-compatible Provider

Alpha 1 正式支持 OpenAI-compatible `/v1/chat/completions`、SSE 流式响应和原生 `tool_calls`。
允许任意 Base URL、手工模型 ID、自定义 Header、代理和 CA 文件；不设置域名白名单。

保存配置时发送最小真实 Tool Calling 探测，验证流式响应、参数 JSON、工具调用和取消。没有 `/v1/models`
不阻止使用；不具备可靠 Tool Calling 的服务只标记为聊天模式，不用文本正则模拟 Agent 工具调用。

### A9-GW02 凭据与 TLS

- API Key 使用 Windows DPAPI Current User 保存；不可用时降级为仅内存。
- 凭据字段、Authorization 和已知敏感环境变量进入 UI/日志/事件前脱敏；普通命令输出只做尽力识别。
- 默认验证 TLS。Provider 可以提供醒目的“不安全 TLS”显式选项，但不能静默降级。
- Provider 凭据不传给模型工具或 Shell。

### A9-GW03 重试、取消与模型切换

- 连接失败、超时、429 和适用 5xx 最多退避重试三次；认证、参数和工具格式错误不盲目重试。
- 生成阶段只要持续收到数据就不使用很短硬超时；长时间无数据时让用户等待、重试或取消。
- 取消同时终止网络请求和 Agent Loop，保留已完成工具结果与 checkpoint。
- 切换模型时从本地标准化事件账本重建上下文，并先显示新模型的工具能力。
- Replay/Mock 只用于开发、测试和验收，不是正式 UI 默认，也不作为真实模型失败后的自动降级。

### A9-GW04 Token 与费用

保存服务端返回的输入、输出和缓存 Token；费用仅在用户配置可靠单价时估算并明确标注。
上下文窗口、最大输出、最大 Agent 轮数和费用警告提供合理默认值并允许用户覆盖。

## 8. Agent Loop、指令与上下文

### A9-A01 指令优先级

当前权限模式与运行时不变量 → 用户当前明确要求 → `AGENTS.md` → 其他被识别的项目指令 → 项目资料与源码。
兼容发现 `CLAUDE.md` 等常见文件，但显示来源和优先级；README、源码和工具输出默认只是数据。

### A9-A02 项目探索

启动只做轻量本地探测：目录、Git 状态、指令文件和常见构建配置。收到任务后按需 `search/read`，
Alpha 1 不引入向量数据库或 Embedding。数万文件工作区必须可以快速打开，任何长扫描都可取消。

### A9-A03 自主执行

- 小任务直接行动；多模块、依赖或高影响任务生成可见计划，Full Access 下无需等待计划审批。
- 可安全回退的细节由 Agent 合理假设并记录；方向性或不可逆决策才暂停询问。
- 测试失败后在预算内自主修复；连续重复无进展三次后暂停并交还用户。
- 只修当前目标或阻塞验证的问题；既有无关失败记为警告。
- 默认只格式化本次修改文件，不顺便全仓库重构。

### A9-A04 上下文与记忆

- 会话历史、工具结果和压缩摘要进入本地事件账本；压缩不能改变指令和权限。
- 不生成不可见的跨任务长期记忆；长期规则由用户确认写入可见项目文件。
- 工具预览有界，完整日志本地保存；模型可以按需继续读取。

### A9-A05 完成状态

只有相关验证实际通过时标记“已验证完成”；代码已写但测试未运行时标记“完成但有警告”，
无法继续时标记“被阻塞”。最终摘要固定包含：完成内容、修改文件、实际验证、未解决问题和撤销入口。

## 9. 会话、并发、状态与审计

### A9-ST01 任务和工作区

- 每个目标形成独立任务，包含 Turn、Run、计划、工具事实和 checkpoint。
- 不同工作区可在独立窗口并行；同一工作区同一时间只有一个写任务持有锁。
- 用户可以查看其他会话；活动写锁不因 UI 切换而丢失。

### A9-ST02 SQLite 事件账本

继续使用版本化 SQLite 结构化实体和不可变事件，不改成 JSONL。完整记录模型请求摘要、工具调用、
命令、输出引用、Diff、审批、取消、恢复和结果；敏感字段先脱敏。

### A9-ST03 中断与恢复

- 应用重启后把活动任务标记为中断，不自动重放模型或副作用；用户显式继续。
- 未完成 Shell 命令不自动重连或重放；托管后台进程仅按 PID/命令探测。
- 迁移前备份数据库；未知 schema、损坏或迁移失败进入受限诊断模式，不覆盖旧库。
- A8 只迁移工作区、非敏感设置和可安全读取的历史会话；旧活动任务不自动继续，旧 Review 提案不自动应用。

### A9-ST04 保留策略

日志与会话默认保留 90 天并设置总空间上限，允许用户改为永久。清理优先删除已结束任务的旧原始日志，
不删除活动 checkpoint 和用户标记保留的任务。

## 10. 桌面产品体验

### A9-UI01 产品形态

- 轻量 Agent 客户端，不重建 IDE。
- 对话居中；左侧工作区/会话，右侧按需展示工具活动、命令输出、代码和 Diff。
- 每个工作区独立窗口；支持系统默认编辑器打开和在文件夹中显示。
- 不内置 Monaco、LSP、调试器或完整编辑器。

### A9-UI02 任务交互

- `Enter` 发送，`Shift+Enter` 换行，运行时主操作为停止。
- 工具时间线默认紧凑展示名称、目标、状态和耗时，可展开完整 Shell、错误和 Diff。
- Diff 支持统一/并排查看、文件级撤销和完整文件打开；行级挑选延后。
- 外部操作审批可以按一个可见计划分组；破坏性操作与普通操作分开显示。

### A9-UI03 首次配置与本地化

首次只要求工作区、权限模式和 Provider；随后运行能力探测。高级代理、CA、预算和 Shell 覆盖不阻塞开始。
默认简体中文，字符串集中管理并提供基础英文；至少验证 1366×768、100%/125% DPI 和中文字体环境。

## 11. 交付与 Runtime Profile

### A9-D01 客户端闭包

- 目标平台固定 Windows 7 SP1 x64；客户端继续复用 Electron 22.3.27、内嵌 Node 16.17.1、
  D-013 native helper、D-014 better-sqlite3/SQLite 的已锁定输入。
- Alpha 1 交付 x64 自包含 ZIP，解压即用且不要求管理员权限；应用数据默认位于
  `%LOCALAPPDATA%\Win7CodingAgent\`，显式 Portable 模式才写程序目录附近。
- Git、Python、项目 Node/.NET、PowerShell 5.1 等作为能力探测项；缺失时局部降级，不导致客户端整体退出。

### A9-D02 升级、完整性与诊断

- 不自动更新；新版本解压到新目录并读取旧用户数据，旧目录可直接回退。
- Alpha 交付必须包含版本清单、SHA-256、SBOM、许可证和确定性构建证据；商业签名不阻塞 Alpha。
- 默认不上传遥测或崩溃信息。支持导出本地脱敏诊断包，排除源码正文、凭据和完整环境变量。

## 12. 首批项目支持

正式实测 Node.js 16、Python 3.8、.NET Framework 4.x 和文本/配置项目。Agent 依靠模型、搜索、
文件工具和项目原生命令工作，不承诺语言专用 AST/LSP。Git、Python、Node、MSBuild 等工具不存在时，
应明确说明缺失能力以及仍可完成的工作。

## 13. Alpha 1 非目标

- DOCX/XLSX/PPTX/PDF 专用编辑与 Office/WPS COM；
- 内置 IDE、LSP、调试器和代码补全；
- 用户交互终端和模型向终端注入输入；
- Browser 自动化与 Win7 Electron 打开不可信网页；
- 多 Agent、插件市场、自动更新、云端同步、移动端；
- 无人值守后台 Agent、托盘常驻；
- 公式重算、宏执行、复杂 PDF 原位编辑。

办公能力不阻塞 Coding Agent Alpha 1。未来 Alpha 2 Office Lite 另立任务书，优先读取和创建简单副本，
不承诺复杂现有文件的高保真编辑。

## 14. 验收合同

### A9-AC01 开发机

- 所有模块 lint/build/test、文档检查和 A9 新增契约测试通过；
- 真实 Provider 完成最小 Tool Calling 探测；Replay 只能作为确定性测试证据；
- Full Access、Review、Read Only、Shell、文件冲突、checkpoint、Git 和恢复的负向/正向矩阵通过。

### A9-AC02 Windows 分层

- 开发机自动化通过后，在 Win7 前进行 Win10 包装和原生闭包 smoke；Win10 结果不阻塞内部 Alpha，
  但进入 RC 前必须补齐。
- Alpha 1 PASS 必须在至少一台干净 Windows 7 SP1 x64 完成同一候选的五条核心旅程。
- Win7 验收同时覆盖中文/空格路径、CP936/UTF-8/CRLF、PowerShell 5.1 与 CMD 降级、取消/残留、
  SQLite 重启恢复、ZIP 完整性和普通用户权限。

### A9-AC03 PASS 裁决

五条核心旅程、数据恢复和干净 Win7 交付必须全部通过；四条通过不能写成 PASS。次要 UI 或 Best Effort
能力可以作为已知限制，但不能破坏代码读取、修改、Shell、验证、Git、撤销和恢复闭环。

## 15. 已确认的取代关系

ADR-0089 只在 A9 范围取代以下旧产品策略：

- ADR-0030 不提供 Full Access 的裁决；
- ADR-0032/C20 要求所有 Git 只能经隔离 Adapter 的裁决；
- C09 对所有模型生成 Shell 字符串的一刀切禁止；
- A8 强制 Review staging、Replay 默认、任意 Shell/Git 写/任意网络禁用；
- C08 对每个非交互命令必须配置固定硬超时的要求。

A9 继续保留 Renderer 隔离、Schema IPC、审计、输出上限、取消、进程树清理、凭据脱敏、TLS 默认校验、
checkpoint、原子写入和 Win7 实机验收。Phase 1/2、A7、A8 和历史验收仍按原合同解释。
