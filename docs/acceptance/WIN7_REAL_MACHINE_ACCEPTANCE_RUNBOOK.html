1. 推荐控制拓扑

Mac 控制机 构建与签名、计算 SHA-256、SFTP 传包、SSH 触发固定脚本、下载证据、RDP 视觉检查。
→
隔离管理网 独立交换机/VLAN；Win7 不配默认网关和 DNS。防火墙只允许来自 Mac 固定 IP 的管理端口。
→
Win7 被测机 短路径本地盘、普通用户为主、管理员仅做前置配置；运行固定验收包并生成证据目录。

推荐至少保留两个可恢复状态：

  1. Clean-Baseline：Win7 SP1 x64 + 已声明 KB；不安装 SSH、Node、Git、编译器或测试工具。
  2. Control-Enabled：从 Clean-Baseline 派生，启用 RDP，并按需安装 SSH/抓包工具。用于传包、自动化和问题定位。

虚拟机用快照；物理机用磁盘镜像/可验证的系统还原方案。完成 E5 干净环境验收前必须恢复 Clean-Baseline，不能只卸载工具后假设恢复干净。

严格零网络场景不能靠 RDP/SSH 同时证明。 Phase 1/2 明确禁止任何网络连接（含 localhost）。若要做字面意义上的断网验收，必须使用虚拟化平台控制台、KVM-over-IP/硬件远程控制或现场人员，随后禁用/拔除所有网卡。 仅“无默认网关的管理 LAN”只能证明无外网，不等于零网络。

2. Win7 机器准备

2.1 硬件与系统

  • Windows 7 SP1 x64，build 7601；保留正版介质/COA 与系统版本截图。
  • 至少 4 核 CPU、8 GB 内存；性能验收优先真实 5400/7200 rpm 机械盘。
  • 至少一台无独显或老旧集显的物理机，用于 SPIKE 01 GPU/软渲染；RDP/虚拟 GPU 数据不得冒充该项。
  • 创建普通验收账户；管理员账户只用于补丁、RDP、SSH 与防火墙配置。正式产品运行以普通用户为主。
  • 测试目录使用本地 NTFS，例如 C:\W7A；另建中文+空格目录，例如 C:\验收 目录。不要把数据库放网络盘。
  • 记录 BIOS/机器型号、CPU、内存、磁盘型号/转速、显卡和驱动版本；性能结果必须标注实机或 VM。

3. 从这台 Mac 控制 Win7

3.1 GUI：RDP / Windows App

Win7 被控端应使用 Professional、Enterprise 或 Ultimate 等可承载远程桌面会话的版本；Home/Starter 不能作为 RDP Host，遇到这类版本应改用硬件 KVM/虚拟化控制台，不要为验收引入来历不明的 RDP 补丁。

  1. Win7 端进入“计算机 → 属性 → 远程设置”，启用远程桌面；优先保留 NLA，不要为省事永久降级认证。
  2. 将普通验收账户加入“Remote Desktop Users/远程桌面用户”，设置非空强密码。
  3. Windows 防火墙仅允许 Mac 固定管理 IP 访问 TCP 3389；不要直接暴露到公网。
  4. Mac 端使用 Microsoft Windows App 添加 Win7 固定 IP，关闭不必要的磁盘、剪贴板、打印机和设备重定向。
  5. 用 RDP 完成窗口、路径、日志、退出和人工确认；GPU 黑屏/软渲染 T04 必须回到物理控制台或硬件 KVM 复测。

微软已用 Windows App 取代旧版 macOS Remote Desktop 客户端。参考：macOS 远程桌面说明。

3.2 命令与传包：SSH/SFTP（验收基础设施，不是产品依赖）

Win7 没有 Windows 10 1809+ 的内置 OpenSSH 功能。推荐在 Control-Enabled 快照安装当前签名版 Bitvise SSH Server，并将其作为验收基础设施单独登记、锁定版本与 SHA-256。

  1. 只允许一个验收账户；先验证密钥登录，再关闭密码登录。
  2. 将 SFTP 虚拟根映射到 C:\W7A；关闭端口转发、代理、远程转发和不需要的子系统。
  3. 如需远程执行，仅开放固定验收脚本的命令行能力；不要将服务配置为“任意 Windows 账户均可登录”。
  4. Windows 防火墙只放行 Mac 管理 IP；记录服务版本、安装器签名、主机密钥指纹和配置导出。
  5. E5 干净验收前恢复 Clean-Baseline；否则 SSH 服务和日志会污染“只装交付包”的结论。

Bitvise 官方说明其 SSH Server 支持从 Windows 11 到 XP SP3 的桌面 Windows，并建议使用近期版本；同时要求限制账户和不需要的服务。参考：兼容性、加固指南。微软内置 OpenSSH 文档从 Windows 10 1809/Server 2019 起，不适合作为 Win7 内置能力依据：OpenSSH for Windows。

3.3 Mac 侧固定操作

先在 Mac 保存 Win7 主机密钥指纹，再使用 SFTP 传递整个已冻结目录。以下只展示固定脚本调用；不要把任意用户输入拼进远程命令。

# Mac：核对验收包哈希
shasum -a 256 win7-acceptance-<commit>.zip

# SFTP：上传到 Bitvise 映射的虚拟根 /inbox
sftp -P 2222 w7accept@192.168.77.20
sftp> put win7-acceptance-<commit>.zip /inbox/

# SSH：只调用包内固定入口，不在线拼装测试逻辑
ssh -p 2222 w7accept@192.168.77.20 \
  'cmd.exe /d /s /c C:\W7A\current\scripts\preflight.cmd'

# 验收结束后取回整个证据目录
sftp -P 2222 w7accept@192.168.77.20
sftp> get -r /evidence/<run-id>/ ./evidence/<run-id>/

若目标是严格断网：先通过 SSH 放好固定任务和证据目录，退出 SSH；切换到虚拟机控制台/硬件 KVM，禁用所有网卡后执行。完成后重新联网只用于取回证据，并把断网/联网边界时间写进报告。

4. 正式验收包合同

每个验收包必须绑定一个干净 Git commit，不允许从当前脏工作区直接打包。建议短路径结构：

C:\W7A\current\
├─ MANIFEST.json                 包版本、Git commit、Profile、创建时间
├─ SHA256SUMS.txt                所有关键工件哈希
├─ SBOM.json                     运行时、DLL、.node、许可证、来源
├─ runtimes\                     Python/Electron/原生运行闭包
├─ phase1\  phase2\             冻结实现与固定入口
├─ spike01\ spike02\ spike03\ spike04\
├─ fixtures\                     无敏感数据的标准夹具
├─ scripts\
│  ├─ preflight.cmd
│  ├─ run_phase1_e1.cmd
│  ├─ run_phase1_e2.cmd
│  ├─ run_phase2.cmd
│  ├─ run_spike01.cmd ...
│  └─ collect_evidence.cmd
└─ expected\                     机器可读 schema 与期望摘要

C:\W7A\evidence\<run-id>\       运行时只写这里

包在离开构建机前必须满足：

  • Git 工作区干净，commit 与 MANIFEST.json 完全一致。
  • 所有运行时、原生模块、外部程序版本已锁；不存在 ^、latest 或现场解析。
  • 关键安装器/二进制 SHA-256 已写入清单并在 Win7 端二次核对。
  • 提供离线启动、超时、输出上限、取消和清理；每个脚本将 stdout/stderr 分开保存。
  • 提供普通用户运行路径；管理员权限只能用于预先声明的系统准备。
  • 提供升级前备份、失败回滚和残留检查；不删除不属于本包的文件。
  • 不包含密钥、真实凭据、用户仓库、数据库、缓存、.git 或开发机绝对路径。

5. 现场执行顺序

5.1 第 0 门：预检与证据开场

  1. 恢复对应基线快照/镜像，记录快照 ID。
  2. 核对 OS、SP、架构、补丁、时区、账户权限、磁盘、GPU、网卡状态。
  3. 核对包 commit、Profile ID、清单和所有关键 SHA-256。
  4. 保存运行前 tasklist /fo csv、netstat -ano、服务列表、磁盘空闲与目标目录树。
  5. 创建唯一 run-id，之后所有日志、截图、抓包和报告都放到同一证据目录。

5.2 Phase 1：E1 / E2

准备性实测已完成，正式 Gate 仍未启动。当前标准树已完成三次 18/18 probe；E2 中文+空格树已完成 17 PASS + 1 预期 degraded、20/20 回归和 compileall。必须仍由架构师把 Phase-Gate 从 REPAIR_REQUIRED_BEFORE_E1 解除后，才能宣称正式 E1/E2。

已完成与仍需人工授权的边界：

  • E2 已完成准备性实测：中文+空格安装/报告路径、Git 不在进程 PATH；18 项中 17 PASS + 1 个结构化 TOOL_NOT_FOUND/degraded，无 blocking check，回归 20/20。
  • E1 待人工 Gate：Win7 SP1 x64 + CPython 3.8.10 x64 + Git 2.46.2 + 普通用户 + 严格断网；需要架构 Gate、授权断网和干净环境。
  • 执行 scripts\run_tests.bat 与 scripts\run_probe.bat；JSON 必须含 18 项，SQLite 快照必须含前 17 项。
  • 检查 proc.timeout、proc.truncate、proc.kill、编码/BOM/CRLF、磁盘空间、TLS 离线内省和报告原子写。
  • 运行前后对比进程；确认父/孙进程均消失，%TEMP% 与工作目录无 cap_probe_ 残留。
  • 两个 BAT 必须为 CRLF；E2 在中文+空格目录双击入口。
  • 原始 JSON/SQLite、回归 stdout/stderr 与 compileall 证据见 validation/phase1。

5.3 Phase 2：只读 Agent

必须使用 phase/02-readonly-agent 的已审查验收包。 当前整合分支不能代替该分支；只有 Gate 已达 READY_FOR_WIN7_VALIDATION 才进入实机。
  • 运行统一入口 scripts\run_agent_tests.bat，实际测试数不得低于冻结门槛。
  • 运行 Mock/Replay 演示；禁止真实模型、网络与写用户代码。
  • 对夹具工作区运行前后做字节级清单对比；除显式 events/report 路径外必须零变化。
  • 重点验证路径上溯/外部绝对路径/symlink 逃逸、中文/空格/%/#、长路径、二进制、Git 缺失和 Replay 不一致。
  • 结果只能是已定义的状态与错误码；stdout/stderr 保持 ASCII。

5.4 SPIKE 01：Electron 生死线

  • 从 Clean-Baseline 解压已打包的 Electron 22.3.27 验证壳，不能执行 npm install。
  • 重启后首次启动 3 次取中位数；空闲 10 分钟采集 Shell/Core 内存。
  • 实际启动独立 utilityProcess，验证 stdin 关闭，不能只检查 API 名称存在。
  • 在中文+空格目录验证日志、userData、CrashDumps；二次启动只聚焦已有窗口。
  • 物理机执行 GPU 禁用/软渲染，无黑屏；RDP 结果只作补充。
  • 触发未声明 HTTP(S)/WS/DNS，结合进程级网络审计与外部抓包证明零意外出站。
  • T01/T04/T05/T08/T09 对应硬门槛失败且 Spike 内不可修复，则 Electron No-Go，转 .NET 4.8 WPF 等价矩阵。

6. 证据如何回收

每次运行建议至少形成：

evidence\<run-id>\
├─ environment.txt              OS/SP/KB/架构/账户/时区/硬件
├─ manifest.sha256.txt          包与关键二进制哈希
├─ commands.log                 固定脚本与实际参数
├─ stdout\  stderr\             每个用例独立日志
├─ process\                     tasklist 前/后、PID 树、残留判定
├─ network\                     netstat、抓包、管理流量说明
├─ performance\                 原始采样、3 次中位数、P95
├─ screenshots\                 UI、GPU、错误与恢复
├─ filesystem\                  运行前后目录/哈希差异
├─ rollback\                    回滚步骤与结果
└─ acceptance.md                PASS / FAIL / CONDITIONAL_PASS

正式验收记录必须保存到 docs/acceptance/YYYYMMDD_<phase-or-component>_<environment>.md，至少写明：

  • 执行人、日期、任务书/ADR、Git commit、Profile ID。
  • OS/SP/补丁、运行时/框架/架构、外部工具精确版本。
  • 交付包、锁文件与关键二进制 SHA-256。
  • 静态、动态、安全检查；原始证据相对路径。
  • 不适用项的任务书依据；失败/降级项和处置。
  • 网络、权限、回滚和残留检查。
  • 唯一结论：PASS、FAIL 或任务书预先允许的 CONDITIONAL_PASS。
门禁状态不能由脚本自行改写。现场脚本只生成客观证据；任务书中的 Win7-Validation、Phase Gate、性能预算状态和 Go/No-Go，必须由约定角色复核证据后更新。 未执行、包哈希不符、使用了未声明依赖、或只有 VM/现代开发机证据时，一律不得写 PASS。

7. 回滚与清场

  1. 先把证据复制回 Mac，并在 Mac 计算目录清单/哈希；至少保留两份。
  2. 正常停止产品与受管子进程；保存最后一次 tasklist/netstat。
  3. 删除时只删除明确属于本次包的目录；不得用广域 del /s 或依赖通配符清理未知路径。
  4. 若安装过 SSH、抓包、Git、Python 或 VC Runtime，用镜像/快照恢复，而不是仅靠卸载声称回到 Clean-Baseline。
  5. 验证无服务、启动项、注册表、进程、临时文件和 userData 残留；任何清理失败写入验收记录。
  6. 更新失败时恢复上一完整包与匹配 schema/config；代码与数据版本必须一起回滚。
