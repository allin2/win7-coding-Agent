# 性能预算基线（PERFORMANCE_BUDGET）

本文件是全项目性能指标的**唯一权威**（ADR-0033）。任何任务书、评审或验收引用性能指标时
只准引用本文件的条目编号，不得内联复制数值。修订本表必须注明依据（实测报告或补充 ADR）。

**值状态（重要）：** 本表全部数值当前为 **`PROPOSED`（工程估计目标）**，随 ADR-0033（Proposed）
一并待裁决，**不是已接受的 Win7 门槛**。它们在被指定 Spike/阶段于 Win7 实机实测、且 ADR-0033
转 `Accepted` 前，不得作为对外性能承诺或验收硬门槛引用。

**状态位规则（ADR-0033 第 2 条）：** 每行预算在被指定 Spike/阶段于 Win7 SP1 x64 实机实测前，
状态保持 `未实测（NOT_MEASURED）`；**禁止纸面达标**。实测后状态改为 `达标 / 未达标 / 有条件达标`，并链接证据。

**参考硬件基线：** Win7 SP1 x64（build 7601）、4 核桌面 CPU、8GB 内存、机械硬盘（5400/7200 rpm）、
无独立显卡或仅老旧集显（P17 风险机型）。预算按此下限制定；更好硬件不得放宽验收。

## 测量纪律

1. 全部实测必须在 Win7 SP1 x64 实机或可复现 VM 上进行（E1/E2 环境语义，见 `docs/EVALUATION.md`）；
   开发机（Win10/11/macOS）数据仅供趋势参考，不得填入状态位。
2. 每次实测产出结构化报告（机器规格、系统补丁、样本仓库、原始数据、中位数/P95），
   存放于对应 Spike/阶段任务书指定的证据目录，并在本表状态列链接。
3. `有条件达标` 必须写明条件（如"仅 7200rpm 盘"）；条件不满足的部署视为未达标。
4. No-Go 触发的降级动作以对应 ADR 为准：#1~#3/#10 → ADR-0028 降级阶梯；#4 → ADR-0031 终端降级；
   #5~#8 → ADR-0033（关键事件同步 + 非关键异步合并；索引超限切远程索引服务）；#9 → 并发降为 1。
5. 修订预算数值属于决策变更：更新本表同时须在 `docs/DECISIONS.md` 追加补充 ADR 或在
   ADR-0033 的修订记录中登记，不得静默改数。
