# EVALUATION — 验证与评估方法

本文件规定"什么叫做完成"。任何阶段产出未通过本文件对应检查，不得标记完成。

## 1. 验证环境矩阵

| 环境 | 定义 | 用途 | 是否强制 |
|------|------|------|----------|
| E1 基准环境 | Windows 7 SP1 x64 + Python 3.8.10 x64 + Git for Windows 2.46.2 + 普通用户 + 外网断开 | 阶段验收（正向能力基准） | 强制，每阶段至少一次 |
| E2 边界环境 | Windows 7 SP1 x64 + 普通用户 + 安装/工作路径含中文及空格 + Git 不在 PATH 或未安装 + 外网断开 | 验证部分能力失败时 Probe 仍可输出完整 JSON（降级路径） | 强制，阶段 1 至少一次 |
| E3 开发回归 | Win10/11 或其他现代环境 + CPython 3.8.10 | 开发期快速回归 | 推荐；通过不代表验收通过 |
| E4 静态检查 | 开发机（macOS/Linux/Windows） | 文档、静态扫描 | 仅限非运行时验证 |

规则：

- **E3/E4 的通过永远不能替代 E1/E2**。验收记录必须注明环境编号。
- **实现可以在 E3（现代开发环境 + Python 3.8.10）上开始并回归**；Win7 环境不是开始编码的前置。
- **E1 与 E2 是阶段验收硬门槛**：未完成 E1+E2 验收前，阶段不得标记为完成。
- 32 位进程探测验证：建议在 E2 机器上额外用 CPython 3.8.10 x86 运行一次 Probe（不改变 E2 定义，作为补充运行，待负责人确认是否升为强制，见 PHASE_01 §10）。

## 2. 静态检查清单（每次提交前，可在 E4 执行）

| 检查 | 方法 | 通过标准 |
|------|------|----------|
| S1 语法级别 | CPython 3.8 `python -m compileall -q src/` | 零错误 |
| S2 shell=True | 全库文本搜索 `shell=True`、`os.system`、`os.popen` | 零命中 |
| S3 裸 open | 搜索文本模式 `open(` 并人工核对 encoding 参数 | 文本模式全部显式 encoding |
| S4 3.9+ API | 按 WIN7_CONSTRAINTS §3 清单逐项搜索 | 零命中 |
| S5 第三方 import | 提取全部 import 并对照 3.8 标准库清单 | 全部属于标准库 |
| S6 未评审依赖 | 对照 WIN7_CONSTRAINTS §6 登记表 | 使用的高风险模块/外部工具均为"批准"状态 |
| S7 控制台非 ASCII | 搜索 `print(` 调用中的非 ASCII 字面量 | 零命中（写文件的除外） |

## 3. 动态验证要求（按阶段）

### 阶段 0/1（文档）
- 文档交叉引用有效：被引用的文件、章节号、ADR 编号真实存在。
- PHASE_01 任务文档包含全部 9 个规定章节（目标/非目标/输入输出/模块设计/错误模型/JSON Schema/测试矩阵/验收标准/禁止事项）。
- 矛盾清单非空即须有裁决记录或标记"待裁决"。

### 阶段 1（实现后）
- 在 E1 执行 Probe：退出码符合约定；JSON 报告可被 `json.load` 解析；报告字段符合 PHASE_01 §6 Schema。`tool.git` 期望值：E1 已装 Git 2.46.2 时为 pass；若 Git 缺失则为 degraded（`TOOL_NOT_FOUND`）。**Git 的 pass/degraded 均不构成 Agent 核心能力失败，不影响本条验收通过**（核心能力失败仅指 `python`、`fs.*`、`proc.*`、报告产出类检查的 fail/error）。
- 在 E2 执行：中文+空格路径下运行成功；Git 不在 PATH 时 `tool.git` 为 degraded（`TOOL_NOT_FOUND`），若 E2 机器实际存在 PATH 内 Git 则 pass 亦可接受；即使存在降级/失败项，JSON 报告仍完整产出且含全部检查项。
- 全部测试矩阵用例（PHASE_01 §7）执行并留存报告文件。

### 阶段 2+ 
- 各阶段任务文档自带测试矩阵；本文件只规定通用规则：
  - 子进程类功能必须含"超时触发"、"孙进程存活检查"、"超过保存上限的输出截断"三个必测用例（上限为参数化配置，默认见 PHASE_01 §4.2）。
  - 文件类功能必须含中文路径、空格路径、CRLF 保持、全部声明编码往返四类必测用例。

## 4. 安全抽查（每阶段验收时）

1. 运行期无网络连接：验收时用本机防火墙/断网环境确认（E1/E2 本身断网即覆盖）。
2. 运行前后对比：除声明的输出文件外，无新增文件残留；注册表无写入（允许 D-008 只读；用导出对比抽查一次即可）。
3. 日志/报告中无环境变量 dump、无凭据类字符串、无证书完整内容。

## 5. 验收记录格式

每次验收在 `docs/acceptance/`（验收时创建）下留存一份记录，命名 `YYYYMMDD_phaseXX_环境编号.md`，内容至少包含：执行人、环境快照（OS/Python/位数）、执行的检查项清单与结果、失败项与处置、报告文件哈希（SHA-256）。

## 6. 质量红线（任何一条不满足即整体不通过）

1. E1/E2 环境下出现未捕获异常。
2. 任何 S 系列静态检查不通过。
3. 探测/测试在目标机器上留下垃圾文件或进程。
4. JSON 报告不能被标准 `json` 模块解析，或缺少 Schema 必填字段。
5. 声称完成但无验收记录。
