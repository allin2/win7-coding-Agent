# A9-31：P1修复修订r4——R规则补足调用形式与嵌套上下文，并定收敛标准

日期：2026-10-05。Status: DRAFT_NOT_APPROVED。请求批准对[修订r3](A9_31_POLICY_P1_REPAIR_R3_AMENDMENT.md)（ADR-0183）中R规则的有限修订及§4收敛标准；
F1不变。仍只到本地修复、验证与Codex复核为止。未在Win7实机验证。

## 1. 依据（Codex第四轮复核r3；我方以HEAD与r3分别编译纯策略求值复现一致）

- Codex确认：r3相对HEAD只有F1与R两处，撤除二者后与HEAD全文相同，**“HEAD为ASK的输入不会被放宽”由构造成立**；在5,122与13,878条两组构造中HEAD ASK→r3非ASK均为0；三轮20个反例两入口40/40为needs_approval、派发0；撤回F1或R时测试分别6、18项变红。
- P1-1（**HEAD与r3均ALLOW**，非回归）：R只匹配ASCII简单变量记号，漏掉`$script:tool`、`${script:tool}`、`${tool-name}`、中文变量名、`` $to`ol ``转义及cmd `@!PKG!`。
- P1-2（**HEAD与r3均ALLOW**，非回归）：递归分析双引号`$()`、cmd `if`/`for … do`载荷时重新计算上下文，外层的控制结构与高影响词丢失，如`$tool='npm'; if (0) {$tool='echo'}; Write-Output "$(& $tool publish)"`。
- P2-1（**r3新增误确认**）：`if ($true) { npm test }`（条件里的`$true`被当成变量调用）、`${tool}='npm'; & ${tool} test`（`${}`花括号被当成控制结构）、
  `$tool='echo'; & $tool 'if npm'`与`& $tool hello # if npm`（单引号数据与注释中的词被当成控制结构）均由HEAD的ALLOW变ASK。

## 2. 修订（只改R的判定条件，仍只会增加确认）

1. **调用形式**：变量记号先去掉cmd `@`前缀与转义（`^`、反引号）再判定；PowerShell接受任意`$`起始记号（排除`$true`/`$false`/`$null`），
   cmd接受任意`%…%`/`!…!`；另对原文中`& ${…}`调用做文本检查（HEAD段切分会拆开带冒号的`${…}`，为保持HEAD读法不变，不改切分）。
2. **何为变量调用**：PowerShell仅当该段由`&`调用运算符引出或带参数时视为调用（单独`$true`、`$x`不算）；cmd的变量展开即为调用。
3. **上下文继承**：控制结构与高影响词在递归进入子表达式、`if`/`do`/`else`载荷、宿主载荷、嵌入串时向内传递；进入宿主载荷时，宿主自身名称
   （`cmd`/`powershell`等）不计为高影响词。
4. **控制结构判定文本**：先去掉`${…}`变量花括号、单引号字符串、注释，双引号字符串仅保留其中是否含`$(`；cmd层去掉双引号字符串。高影响词仍在全文上判定（载荷常在引号中）。

**原型验证（scratchpad，非证据）**：上述第四轮P1的7个输入（含`${script:tool}`变体）全部ASK；P2的4个输入恢复ALLOW；三轮20个反例全部ASK；
测试语料+432组合+反例共775条中HEAD ASK→新版非ASK为0；语料中新增ASK与r3完全相同（无新增误确认）。

Shell Policy是“尽力识别、歧义保守确认”的识别器（ADR-0171），不是解析器，复核总能构造出HEAD也放行的新写法。建议本轮起以下列标准判定能否进入源码提交：
