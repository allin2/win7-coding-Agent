## Win10 返工优化的具体交付项

| 工作 | 必须覆盖的历史反例 | 接入条件与边界 |
|---|---|---|
| 工具真实入口稳定性 | Renderer 表达式实际序列化；重启实际文件创建；NT 设备路径父进程分类；短命进程与时钟边界 | 先用已有真实失败数据回放，再在实际 PS5.1/Electron/普通身份下检查；不以 helper 自测代替真实调用点 |
| 运行输入生成 | 新 source、当前根回执、fresh run ID；禁止复制旧 PID/creation ticks | 冻结前核对全部派生物；规则配置与本轮运行事实分开；新版本不得覆盖旧输入 |
| 产品与取证身份解耦 | 产品更新后沿用旧取证组件，不伪造其构建 source | 取证组件绑定自己的源码、工具链、参数和字节；运行记录另绑定产品。先修订未来合同，再接新候选；旧控制器不改判 |
| 退出 UI 操作 | StopExit 超时、点错 ReleaseExit | 自动化须经过真实对话框入口，按标题/按钮语义核对并记录实际 response。无法可靠自动化时先就位，每轮明确一个动作；不直接注入模拟回执 |
| 成本分项 | 工具准备/修复、产品执行、审批等待、人工操作 | 沿用任务记录写实际起止与分类；无法取得计时则 UNKNOWN，不把等待时间全部归因产品 |

这五项优先于扩大共享 driver 或大文件拆分。它们不要求同时重做全部历史套件。
