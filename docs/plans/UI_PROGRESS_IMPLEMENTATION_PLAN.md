## 4. 中间态与文字反馈合同

### 4.1 真实事件映射

| 事件/情形 | 用户可见内容 | 约束 |
|---|---|---|
| 接受请求 | 已收到任务，准备开始 | 立即反馈，不声称已读取文件 |
| model_thinking / 请求开始 | 等待模型响应 | 不暴露内部推理，不虚构正在进行的具体动作 |
| tool_start | 正在读取相对路径 / 正在运行命令 | 开始不等于完成 |
| tool_end | 成功/失败/取消 + 安全摘要 | 解析真实结果，不把任意返回当成功 |
| plan_updated | 已完成/当前/待做步骤 | 保留模型计划与实际事实的区别 |
| approval pending | 暂停原因、完整命令、目标、工作目录、影响 | 决定绑定现有批准身份 |
| approval resolved | 决定、时间、目标留痕 | 批准后才进入真实执行；拒绝不执行 |
| cancelling | 正在停止，等待清理确认 | 不立刻写已清理 |
| 未确认清理 | 未确认/残留警告 | 继承现有阻断与恢复规则，不照搬 Demo 人工按钮 |
| complete/failed/interrupted | 最终结果、限制、历史记录 | 去重且不覆盖先前失败 |

工具结果里错误返回、退出码非零、取消和外部变化事件都须分别归类。tool_end 可能不是普通调用终止，例如仅报告 externalChanges；不能只按事件名决定状态。

### 4.2 自然语言进度说明

必须实现可见、持久化的简短行动摘要，不能仅补一个转圈或依赖最终答案。

- 模型约定在关键节点提供面向用户的简短说明，并继续正常工具调用。
- 优先复用现有响应 content 和工具轮次边界；先核查实际 Provider tool_calls/content 行为，再决定是否需要新增专门说明事件/工具。
- 中间文字与 final answer 类型分开；最终内容只呈现一次。
- 不假设每个 Provider 都输出说明；缺失时仍以真实工具活动/等待反馈兜底。禁止填充未经观察的“已检查/验证成功”。
- 禁止展示 reasoning/thinking 内部字段。模型说明是说明文本，不是权限或批准指令。
- 若新增专门进度工具，必须先在新任务书/ADR 中冻结名称、schema、调用限制、审计与模型兼容性；不能临时绕开工具合同。
- 不按固定时间强迫模型生成进展；长等待由系统计时。
- 真实支持的 Provider 至少完成一次多工具任务验证；夹具不能代替这一条。

### 4.3 安全、顺序与恢复

在契约阶段冻结版本化的 UI 投影 DTO（建议字段，最终由 ADR 确定）：
schemaVersion、workspace/session/conversation/task/turn 绑定、eventId、sequence、stepId、toolCallId、type、status、timestamp、summary、受限详情引用。

- eventId 稳定，重连/轮询不重复；sequence 用于排序，不能仅依赖时间戳。
- toolCallId 不足时在调用开始处补稳定身份，禁止通过“最近同名工具”配对。
- 不允许新事件串入别的工作区/对话/轮次。
- 快照短窗口不能作为完整历史。提供按轮次的有界加载/游标或等价恢复路径；明确截断而非静默丢失。
- 建议先沿用 500ms 轮询，不默认新增 push IPC。传输变更必须说明收益、授权校验和取消订阅。
- 新事件收到后目标约 1 秒内显示；长列表避免每次全量重建，保留展开态、选择、滚动、焦点。
- 长输出/长说明制定字节或字符上限与节流；由 ADR 冻结具体数字，测试边界。
- 凭据跨 chunk 拼接是风险点：不能逐片脱敏后立即展示而遗漏被拆开的秘密。必须验证跨片段识别或采用有界缓冲完整语义段的安全方案。
- 说明、路径、命令和输出按不可信文本渲染；不得直接 innerHTML 插入模型/文件/命令内容。
- 审计存储与 Renderer 展示分清职责；草稿继续走现有 DPAPI，不使用 Demo sessionStorage。
- 重启后恢复已有记录和中断事实；不恢复旧进程、不重发请求、不复用旧审批。
- 旧记录缺少中间态时明确“历史记录未包含过程”，不合成过去活动。
- 优先兼容现有事件表，通过版本化 payload 扩展；如果必须改 schema，单列备份/迁移/回滚、旧库/未来版本拒绝与 Win7 风险矩阵。
