# Coding Agent UI 方案 02 — 经 grilling 确认的设计基线

日期：2026-09-08
用途：本地交互 Demo 与后续产品实现的设计依据。当前只交付 Demo，没有修改产品实现或开放历史任务授权。

## 1. 已确认的核心目标

让用户在请求与结果之间持续知道：现在做什么、已经完成什么、为何等待、是否需要自己行动。

- 自然语言进度说明与系统工具状态同时提供。
- 说明出现在开始、重要发现、方向变化、阻塞和进入验证时，不为每个工具生成段落。
- 连续工具活动组成可展开的活动组，失败、审批和结果独立突出。
- 等待超过 10 秒后显示等待对象与实际等待时长，不编造进度百分比。
- 保存简短说明、工具活动与决定，绑定对话和轮次；重新打开可回看。
- 重启后未完成任务显示中断，旧审批失效，不自动重放。
- 正常事件收到后约 1 秒内可见是产品实现目标，不是当前目标端已测结论。
- 全文搜索暂不纳入；标题搜索覆盖当前工作区的活动与归档对话。

## 2. 页面职责

| 区域 | 设计职责 |
|---|---|
| 顶栏 | 工作区选择、运行时、模型连接、工作区权限、检查器入口 |
| 左侧 | 新建、标题搜索、待处理、最近、重命名、归档与恢复 |
| 主对话 | 请求、关键说明、计划、工具组、审批留痕、结果；每轮独立保留 |
| 输入区 | 发送、停止、处理中原因、等待时长、草稿状态 |
| 文件页 | 示例目录浏览、上一级、文件预览、查找、跳行、编码入口 |
| 变更页 | Checkpoint 对应 Diff、撤销范围、Git 状态刷新 |
| 活动页 | 逐项记录、时间、原始输出与复制 |
| 环境页 | 当前分支与推送目标分开呈现、权限、Shell、模型与运行时状态 |
| 设置 | 模型连接表单、失败反馈、企业网络与 Shell 关键入口 |

暖色中性背景、青绿色主色、琥珀色待处理与红色错误沿用参考稿。小窗口优先保证对话可读，侧栏按需展开。折叠、键盘焦点与标签页方向键均在原型中提供。

## 3. 过程反馈语义

| 条件 | 展示 | 不能表达为 |
|---|---|---|
| 模型请求已发出 | 等待模型响应、已等待时长 | 模型正在检查某具体文件 |
| 工具开始 | 正在读取某文件、运行某命令 | 已成功读取或执行 |
| 工具返回成功 | 成功及有依据的结果摘要 | 仅因返回就推断整体完成 |
| 工具失败 | 原步骤标失败，保留错误；重试另起记录 | 把旧失败原地改成成功 |
| 等待审批 | 暂停原因、目标、工作目录、完整命令 | 已开始执行 |
| 已批准 | 保留批准记录，再出现执行活动 | 批准就等于执行成功 |
| 正在停止 | 收到取消请求，等待清理结果 | 立即宣称所有进程已清理 |
| 清理未确认 | 明确残留不确定性，阻止后续自动执行 | 显示已安全停止 |
| 重启恢复 | 中断事实和已有历史、失效审批 | 自动恢复旧命令执行 |

自然语言仅呈现用户可读的行动与发现摘要，不展示内部推理，不把模型意图当成已执行事实。没有模型进度文字时，工具事件仍提供基础反馈。

## 4. 当前源码可行性

检查基础为当前 codex/ui-optimization 工作树；产品代码未修改。

| 源码 | 现有基础 | 后续实现工作 |
|---|---|---|
| src/core/src/a9-agent-loop.ts | model_thinking、model_chunk、tool_start、tool_end、plan_updated 等事件 | 核对事件身份、步骤边界和结构，确保用户说明与工具事实分开 |
| src/shell/product/a9-agent-runtime.js | onEvent、安全投影、时间线与记录；model_chunk 先缓存 | 设计有界、节流、脱敏后的实时说明投影；不能直接暴露原始片段 |
| src/shell/product/renderer/a9-workbench.js | 500ms 快照轮询、侧栏时间线；对话主要渲染 requestPrompt/finalMessage | 主对话按轮次合并进度与工具活动，避免重复、错序、重绘丢焦点 |
| src/shell/product/renderer/workbench.html | 归档、恢复、草稿、设置、文件查看、Diff/Undo 等既有入口 | 保留现有能力并重组层级，不因视觉简化而删功能 |

结论：
1. 系统活动状态有明确事件基础，可实现；具体 DTO 完整性和运行行为仍须验证。
2. 自然语言即时说明涉及模型约定、运行时缓存投影和界面渲染，不能只靠 CSS。
3. 历史回看要验证现有事件存储能否重建到每轮；不能假设有限长度的内存时间线就是完整历史。
4. 500ms 轮询提供可利用的更新路径，不等于已证明事件到界面在 1 秒内显示。
5. 产品接入还需按仓库规则建立适用任务书与允许路径；本文件不是实现授权。

## 5. Demo 覆盖与限制

已提供交互：
- 标题搜索（含归档）、重命名、新建、归档和恢复；按工作区隔离。
- 两个示例工作区及 Full Access / Read Only 切换。
- 多轮消息历史、精简计划、关键节点说明、连续工具折叠组。
- 审批批准/拒绝、决定时间、绑定目标、完整命令留痕。
- 运行中、长等待、失败、重试、正在停止、停止、清理未确认。
- 本标签页会话存储历史与草稿；刷新或模拟重启将活动任务标为中断。
- 目录、文件内容查找和跳行、Checkpoint Diff 与模拟撤销、Git 刷新、输出复制。
- 模型配置与探测成功/失败演示、未配置时禁止发送。
- Ctrl+K 搜索、Ctrl+I 检查器、标签页方向键；不设置全局 Enter 批准。

显式限制：
- 所有文字、工具、输出、等待与成功均为预设模拟，不调用模型或真实命令。
- 进度文字采用预设示例，不证明真实 Provider 能稳定生成同类文字。
- sessionStorage 是未加密、限当前标签页会话的演示保存，不能当成产品 DPAPI 持久化。
- sessionStorage 不可用时明确降级为内存；关闭标签页后的长期保存不在 Demo 范围。
- 文件预览内容是示例字符串；编码选择不实施原始字节重新解码。
- 设置只覆盖关键表单与反馈；真实密钥输入关闭，完整 Header/环境变量编辑尚未展开。
- 模拟人工确认清理仅用于观察恢复路径，不替代真实清理证据。
- 完整 Review、附件上传、对话全文搜索没有伪装成可用能力。
- “对话/任务”合并为任务对话，每个对话可有多轮，无额外任务列表页面。

## 6. 推荐体验顺序

1. 选择“读取 → 修改 → 验证”，点击“播放流程”，观察约 6 秒的进度与工具记录。
2. 展开活动组；到变更页查看本轮 Diff、撤销范围。
3. 选择“外部写入审批”，批准或拒绝；检查结束后决定仍在历史中。
4. 选择“长时间等待模型”，等待 10 秒以上，查看等待时长，再停止。
5. 选择“工具失败 → 重试”，失败后新建一次重试，比较两轮记录。
6. 选择“停止但清理未确认”，开始后停止，查看诊断与后续执行锁定。
7. 在活动任务期间点击“模拟重启”；确认中断与旧审批失效。
8. 新建、重命名、搜索、归档和恢复对话；切到只读工作区，确认 Shell 场景禁用。
