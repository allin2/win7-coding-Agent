# A9-39 / WIN7-46 批次 2 验证套件

候选 WIN7-46 是暂定编号：冻结前由执行代理按引用、登记和目录核对，ADR-0155 仍为 Proposed。
本套件不授予任何放行权限；是否具备批次 2 执行能力只由负责人在门 B 裁决。
结论上限固定为“批次 2 执行能力”，不是完整 Alpha 2，也不是 RC。

## 运行方式

1. 负责人批准授权文件，并把它的 SHA-256 单独告知执行代理。
2. 执行代理为每个阶段生成一个请求文件；请求绑定运行编号、四个哈希、目标身份和 900 秒有效期。
3. 控制器校验请求，写入账本，再运行唯一推导出的命令：候选 `electron.exe` 的 Node 模式加一个套件脚本。
4. 阶段脚本把原始文件写进该次尝试自己的目录；失败和重试不会覆盖更早的原始证据。
5. 阶段结束后账本记录 `phase-result.json` 的哈希；账本只能追加。
6. 消费请求时先独占创建该次尝试目录；同一请求被第二次消费会以 `A9_BATCH2_REQUEST_ALREADY_CLAIMED` 停止。崩溃遗留的占用让该索引保持关闭，由操作者记录原因，不复用。
7. 同一请求索引只允许一个占用：同索引已存在任一阶段的占用目录时，消费方停止并释放自己的空目录，两个并发消费方都可能退让，但不会都成功。
8. 完成记录必须对应同索引、同阶段、同运行、同摘要的消费记录，只能写一次；PASS 完成还要求结果文件本身为 `PASS`。报告复核把没有消费记录的完成项判为 `LEDGER_COMPLETION_ORPHAN`。
9. 完整性阶段和报告阶段都从请求取得同一份授权文件路径与 pin；报告阶段缺少授权文件时请求被拒绝。

请求里没有自由文本命令字段。控制器不接收任何其他命令。

## 结果如何判定

阶段通过的唯一依据是 `phase-result.json` 为 `PASS`，且其中每个用例的每条断言都有非空的观察值。
控制器的退出码为 0 不构成通过。驱动无法观察的事实记为 `UNKNOWN`，并写明原因；任何断言都不预先记为 `NOT_PERFORMED`。
阶段一旦带失败类（驱动 `ERROR`、驱动非零退出、密钥或残留发现、复核失败），阶段结果必为 `FAIL`，此前记录的 PASS 断言不能改变这一点。

## 退出与身份证据的范围

| 项 | 范围 |
|---|---|
| 产品退出码与时间 | 只记父进程直接启动的产品进程；driver、helper、Shell 子孙进程的退出码从外部不可读，不声称 |
| 子孙进程退出 | 退出前树按“进程号加创建时间”核对，退出后不存在则通过，并记录观察缺席的时刻 |
| 树未观察 | 退出前树查询失败、树为空或退出后进程列表失败时，该断言为 `UNKNOWN`，不是 `PASS` |
| 进程列表 | 命令抛错、退出码非 0、带错误对象、超时，或输出超过 256 KiB 被截断，都按列表失败处理，不证明“进程不存在”（记 `UNKNOWN`）。失败列表里已完整输出的行仍是“进程存在”的证据：退出前树的存活进程或残留进程出现在其中时记 `FAIL`。被截断的半行不算证据。环境阶段、正常退出、后飞行三处都按此处理 |
| 控制器 Job 判断 | 查询调用失败时身份写 `null`，请求脚本按不等于批准值拒绝，不当作“不在 Job” |
| 布局缩放 | 1366x768 在页面缩放 100% 与 125% 观察，不是 Windows DPI 缩放；继续卡按钮必须出现并可用，否则 `UNKNOWN` |

## 退出时留给系统（B2-BG-03 第 2 条）

p05 的最后一个模式 `release_exit` 启动一个最长 300 秒的后台命令，然后在产品自己的退出对话框里点第二个按钮“留给系统后退出”。点击由桌面控制器完成，不由驱动完成。

| 事实 | 由谁观察 | 判定 |
|---|---|---|
| 对话框三个按钮名与返回序号 1 | 驱动 | 按钮名不符或序号不是 1，为 `FAIL` |
| 归属事件依次为 owned、release_intent、released，且两次释放号相同 | 驱动读取 SQLite | 顺序、释放号任一不符，为 `FAIL`；读取失败为 `UNKNOWN` |
| 产品退出码为 0，未被超时或标记终止，点击状态为 0 | 套件（父进程） | 任一不符，为 `FAIL` |
| 句柄自己的进程（驱动退出前记录的进程号和创建时间）在产品退出后仍存活 | 套件 | 已不存在为 `FAIL`，其后代存活不能代替；进程树查询失败、句柄进程号不在记录的进程树里或创建时间为空，为 `UNKNOWN` |
| 候选目录和 `driver-electron` 目录内没有产品进程（按目录边界匹配，同前缀的兄弟目录不算） | 套件 | 有残留为 `FAIL`，退出后最多等待 10 秒；列表不可用且未见残留为 `UNKNOWN` |
| 套件按进程号加创建时间终止被释放的命令及其后代，并连续两轮观察不存在 | 套件 | 终止不掉为 `FAIL`；列表不可用或有后代缺创建时间为 `UNKNOWN` |

套件只终止驱动在退出前记录过身份的进程，以及在这些进程存活时发现的后代，按进程号逐个终止，不终止进程树。首次退出后采样、产品收尾采样和清理采样发现的后代都持续追踪，父进程结束后仍存活的后代继续计入清理结果。`release-held-exit.json` 的 `cleanup.samples_before_cleanup` 保存清理前采样中识别出的实例。已知进程号的创建时间缺失时，不终止该实例，也不将其计为已消失；清理结论为 `UNKNOWN`。命令自身在 300 秒后结束。
三值判定里只有全部检查严格为 `true` 才是 `PASS`；缺失或非布尔值是 `UNKNOWN`，任何 `false` 是 `FAIL`。
释放后辅助进程是否继续存活是待验证事实（`UNKNOWN`）：它若仍在候选目录下运行，会被记为产品残留，这是一条发现，不是套件缺陷。
